# V27 성장·장비·방치 마감 검증

검증일: 2026-09-22. 대상: Godot 4.7.2, V26 기반 성장 영역.

주관적인 완성률 대신 아래 게임 동작과 경계를 검증했다. 새 `V27GrowthEconomySmokeTest.gd`는 40개 검사를 수행하며 모두 통과했다. 기존 관련 9개 테스트도 모두 종료 코드 0으로 통과했다.

## 구현과 마감 기준

| 기준 | 수정 내용 및 증거 | 상태 |
|---|---|---|

| 장비 교체 보존 | 수동/직접 장착은 같은 인벤 슬롯에 이전 장비 반환. 자동 드랍도 이전 장비를 보관 또는 기존 자동분해 정책으로 환전. +10 일반 장비를 더 약한 +1 고등급으로 덮어쓰지 않음 | 통과 |

## 실제 수정한 결함

- 이전 자동 드랍은 등급만 비교하여 강화한 장비를 약한 장비로 덮어쓰고 기존 장비를 삭제했다.
- 인벤 정규화는 원본을 변경하고 음수 레벨을 허용했으며, 표시 전투력과 실제 슬롯 전투력 계산이 달랐다.
- 화면이 교체된 후에도 오래된 인벤 버튼의 인덱스가 다른 장비를 가리킬 수 있었다.
- `max(1, 보상 / 인원)` XP 분배는 작은 보상을 부풀렸고 나머지 XP는 버렸다. 영웅·동료 레벨 상승 루프에는 상한이 없었다.
- 영웅 돌파는 표시 전투력도 즉시 갱신하지 않았다. 승급·돌파에 존재하지 않는 영웅 입력 검증이 없었다.
- 동료가 전투 중 진화해도 지원 런타임 레벨·진화 상태가 즉시 바뀌지 않았다.
- 오프라인 추정기를 직접 호출하면 시간과 보상 입력에 자체 상한이 없었고, 초기 저장 timestamp가 0이면 최대 보상을 생성했다.

## 통합 확인 및 남은 한계

- 영웅 전투 스탯 즉시 반영을 `_refresh_hero_growth_stats()`와 연결했고, 실제 XP·장비·스킬 투자 후 HP 비율·사망·버프·궁극기·쿨다운 보존을 [전투 중 성장 통합 검사](V27_LIVE_GROWTH_KO.md) 34개 조건으로 확인했다. 전투 중 성장 변경이 화면을 재생성하며 전투 상태를 비우던 연결 오류도 수정했다.
- 저장 후 새 Main을 만들어 장비·성장 상태 보존 및 재실행 시 방치 보상 중복 차단을 [저장 통합 검사](V27_PERSISTENCE_INTEGRATION_KO.md)에서 확인했다.
- 서버가 없는 로컬 저장 방식이므로 사용자가 기기 시간을 의도적으로 앞으로 조작하는 것까지 증명된 서버 시간으로 막는 방식은 아니다.
- 자동 장착은 방어 세트 효과를 보수적으로 보존한다. 세트를 깨고 공격력을 올리는 선택은 수동 장착으로 가능하다.
- 레벨·장비·스테이지 상한은 현재 프로토타입의 운영 범위다. 장기간 실사용 경제 통계, 신규 장비/스테이지 콘텐츠, 실제 기기 장시간 성능 검증은 별도 작업이다.
