# 자동사냥 AI v4 변경 안내

업로드된 `pixel-faction-rpg-prototype-enhanced-fx-v3.zip`을 바탕으로 수정한 Godot 4.5.1 프로젝트입니다. 기존 캐릭터 이미지·몬스터 이미지·진영·사냥터를 사용합니다.

## 실행

1. ZIP을 새 폴더에 풉니다.
2. Godot 4.5.1에서 `pixel-faction-rpg-prototype/project.godot`을 가져옵니다.
3. 최초 리소스 가져오기가 끝나면 F5로 실행합니다.
4. 진영과 영웅을 선택하고 사냥을 시작합니다. 사냥 화면 오른쪽의 `일시정지`와 `사냥 재개`로 동작을 확인할 수 있습니다.

이 파일은 소스 프로젝트이며 APK나 iOS 실행 파일은 포함하지 않습니다.

## 바뀐 동작

| 항목 | v4 동작 |
|---|---|
| 목표 선택 | 이동할 수 있는 가까운 사냥 지점을 선택합니다. 방문 횟수를 함께 고려해 같은 두 지점에만 머물지 않습니다. 선택한 대상은 처치·이탈·경로 무효화 전까지 유지합니다. |
| 이동 | 매 물리 프레임에 초 단위로 이동합니다. 셀마다 새 트윈을 만들던 방식을 제거해 중첩 이동과 셀 사이 정지를 줄였습니다. |
| 편대 | 역할에 맞춰 서로 다른 위치를 유지합니다. 이동 방향으로 걷고, 전투에서는 조우 지점을 향해 공격합니다. |
| 공격 | 영웅별 시작 시차와 짧은 공격 준비 동작을 적용했습니다. 실제 피해는 준비 동작 뒤에 반영합니다. |
| 스킬 | 이동 중에도 재사용 대기시간이 흐릅니다. 일시정지 중에는 멈춥니다. 치유는 파티 체력 72% 이하에서 사용합니다. |
| 직업 효과 | 기사 방어와 마도사 약화는 시간이 지나면 풀립니다. 모르가스는 피해 증폭 저주, 발레리아는 스킬 피해에 따른 흡혈, 브론은 피해와 짧은 기절을 적용합니다. |
| 위험 대응 | 파티 체력이 22% 이하이면 전투에서 이탈해 재정비합니다. 체력 85%까지 회복하면 자동으로 다음 사냥을 시작합니다. 체력 0인 상태에서 사냥 보상을 벌지 않습니다. |
| 처치 | 처치 보상은 조우당 한 번 지급합니다. 0.65초간 사망 연출을 유지한 뒤 다음 대상을 선택합니다. 죽은 몬스터와 보스는 반격하지 않습니다. |
| 재탐색 | 대상이 없거나 갈 수 없으면 잠시 기다린 후 다시 찾습니다. 길 또는 대상이 무효화되면 기존 공격 준비 상태를 취소합니다. |
| 화면 전환 | 기존 전투 타이머·영웅 참조·화면 소속 효과를 정리합니다. 이전 화면의 전투가 뒤에서 계속 실행되지 않도록 했습니다. |
| 보스전 | 시작 버튼을 연속으로 눌러도 타이머가 늘어나지 않습니다. 방어·약화 효과를 보스의 실제 공격에도 반영합니다. |
| 보상 저장 | 미수령 골드·경험치를 저장합니다. 임시 파일에 쓰기를 마친 후 저장 파일을 교체합니다. 같은 접속 중 화면을 다시 열어 온라인 시간까지 방치 보상으로 받는 문제를 막았습니다. |
| 조작 화면 | 화면 아래로 밀려나던 보상 수령·일시정지 버튼을 고정 위치로 옮겼습니다. 긴 사냥터 정보와 최근 기록은 오른쪽 패널에서 스크롤할 수 있습니다. |

스킬 효과음은 만들어 둔 짧은 음원을 재사용합니다. 단일 이미지 몬스터의 공격·피격 동작은 실제 지속시간을 기준으로 끝나고, 등장 확대 및 투명도 연출과 충돌하지 않도록 분리했습니다.

## 기존 저장 데이터

게임 이름과 `user://pixel_war_save.json` 경로는 유지합니다. 기존 지갑·영웅 성장·장비·레이드 기록은 읽으며, v4에서 추가한 미수령 보상 필드가 없으면 0으로 처리합니다. v3에서 이미 저장되지 않아 사라진 보상을 복구하는 기능은 아닙니다.

영웅별 실시간 HP와 여러 몬스터가 동시에 움직이는 전장은 아직 구현되어 있지 않습니다. 현재의 **파티 공용 체력 + 한 번에 한 조우** 전투 구조를 개선한 버전입니다. 화면을 새로 열면 실시간 조우·위치·스킬 상태는 새 사냥으로 시작하며, 처치로 얻은 성장과 보상은 유지됩니다.

## 코드 위치와 조정값

- `scripts/AutoHuntController.gd`: 상태 전환, AStarGrid2D 경로 탐색, 목표 유지, 재등장·재탐색 시간, 이동 속도.
- `scripts/Main.gd`: 전투 판정, 영웅별 공격 준비, 스킬 사용 조건, 파티 회복, 보상, 화면 연결.
- `scripts/HeroSpriteController.gd`: 매 프레임 같은 걷기 애니메이션을 재시작하지 않도록 처리.
- `scripts/MonsterSpriteController.gd`: 절차적 공격·피격·사망 연출의 지속시간과 등장 효과 분리.
- `scripts/HeroSpriteFactory.gd`: 전용 스프라이트가 없는 영웅에게 임시 색상 마커를 표시. 새 캐릭터 원화나 전용 공격 프레임을 추가한 것은 아닙니다.

| 설정 | 기본값 | 위치 |
|---|---:|---|
| 이동 속도 | 170 px/초 | `AutoHuntController.MOVE_SPEED` |
| 사냥 지점 재등장 | 6초 | `RESPAWN_SECONDS` |
| 처치 연출 유지 | 0.65초 | `LOOT_SECONDS` |
| 탐색 재시도 | 0.5초 | `SEARCH_RETRY_SECONDS` |
| 영웅 공격 준비 | 0.15초 | `Main._advance_hunt_attacks` |
| 영웅 기본 공격 대기 | 명중 후 0.8초 | 같은 함수 |
| 치유 사용 체력 | 72% 이하 | `Main._should_use_skill` |
| 재정비 진입 / 복귀 | 22% 이하 / 85% | `Main._advance_auto_hunt` |

공격 스킬 피해는 전체 파티 전투력을 영웅 수로 나눈 값을 기준으로 계산합니다. v3의 초반 단발 처치가 줄어들어 전투 속도와 난이도가 달라질 수 있습니다. 현재 UI의 편성 한도는 기존 3명입니다. 최종 10인 파티·개별 체력·전열 충돌 회피는 다음 단계에서 별도 설계가 필요합니다.

## 검증

검증 결과는 `VALIDATION_KO.md`와 `test-results.json`에 들어 있습니다. 전체 재실행에는 Python 3과 Godot 4.5.1이 필요합니다.

```bash
python tools/run_tests.py --godot /path/to/godot --output test-results.json
```

Windows에서는 `--godot` 뒤에 Godot 실행 파일 경로를 지정합니다. 제공한 실행기는 Linux/Windows의 임시 사용자 데이터 폴더를 사용해 실제 플레이 저장 파일과 테스트를 분리합니다.
