# v83-6 레이드 역할 기여도 / 삼국지 SLG식 전선 거점

## 기준과 범위

v83-3 전체 ZIP에 v83-4 growth-lab 및 v83-5 combat-war 증분 패치를 적용한 실제 v83-5를 복원했다. 복원 당시 기존 최종 검사에 기록된 스크립트·씬 325개 SHA-256과 일치했다. 입력 v83-3 ZIP의 SHA-256은 `7a2b39247db1a91ec63f1e7b51b5f332867e3aa112501fd23b03c4d1b5f3d023`이다.

사용자가 제공한 Linux Godot의 실제 버전은 `4.7.2.stable.official.ed1daf0bf`다. 이번 범위는 로컬 게임 플레이이며 계정·클라우드·온라인 PvP·길드·신규 그래픽·음원은 추가하지 않았다. 배포 ZIP도 만들지 않았다.

### 전선 거점 이동

정찰 준비와 전투 보고서의 현재 부대 후속 행동 영역에서, 보급이 연결된 소유 요새·대성·수도 중 현재 위치가 아닌 최대 4곳을 보여준다. 실제 행군 경로가 존재해야 후보가 된다. 군량으로 이동 가능한 후보를 우선하고 다음으로 가까운 곳을 정렬한다.

버튼을 누르는 것만으로 부대를 순간이동하거나 군량을 차감하지 않는다. 그 위치의 기존 정찰·출정 확인으로 연결하고 원래의 권한 검사·행군 비용·시간을 사용한다. 별도 새 거점 건설이나 오프라인 약탈은 없다.

### 군량을 쓰는 현장 재정비

행군 중이 아니고, 부대가 수도 보급망과 연결된 **자신의 요새/대성**에 있어야 한다. 한 번에 피로를 최대 20 낮추고 출전 영웅의 진영전 잔존 HP 비율을 최대 15%p씩 복원한다. 100%를 넘지 않는다. RPG 영웅의 실제 레벨·최대 HP를 영구 증가시키는 기능이 아니다.

비용은 `40 + 실제 피로 감소 × 2 + ceil(실제로 복원한 HP 비율 합계 × 100)` 군량이다. 예를 들어 피로 20을 줄이고 10명 모두 HP 비율 15%p를 복구하면 230 군량이다. 이미 정상 상태면 비용을 쓰지 않으며 군량 부족·적 거점·보급 단절·이동 중에는 거절한다. 대기 타이머는 없다. 수도 도착 시 기존 회복 규칙은 유지한다.

확인창의 부대·위치·부상·피로 조건을 다시 검사하고 실제 지불 가능한 군량을 확인한다. 같은 명령 재전송은 캐시된 결과를 반환하며 다시 차감·회복하지 않는다. 예전 견적을 새로운 명령에 붙여 다시 쓰는 것도 거절한다. 자연 군량 회복만으로 견적을 무효화하지는 않는다.

정비 시 이전 상태의 유령 부대를 남기지 않도록 **해당 플레이어 부대의 주둔·집결 등록을 해제**한다. 다른 아군은 제거하지 않으며 필요하면 집결 지휘자를 이어준다. 화면에 재등록 필요 안내를 넣었다. 비용·회복량은 초기 튜닝값이며 장기 전쟁 경제 균형을 입증한 것은 아니다.

### 왕복 군량 예상

현재 경로로 점령 성공 후 같은 길을 되돌아올 때의 **현재 출발지 왕복 예산**과 부족분을 보여준다. 원래 편도 행군 비용을 사용한 예상이며 수도까지 귀환 비용을 보장하지 않는다. 소유권·전황·경로가 달라지면 실제 이동 조건도 달라진다는 설명을 표시한다. 예상 조회 자체로 월드·군량·난수 상태를 변경하지 않는다.

## 2. 레이드 역할 기여도 분석

레이드 화면의 `레이드 분석 · 최근 기록`에서 전투가 끝난 뒤 확인한다. 본체 피해, 대지 갑주 피해, 광산 수정핵 피해를 **실제로 소모된 HP** 기준으로 별도 집계한다. 세 합계는 기존 `raid_damage_dealt`와 대응한다. 초과 피해는 기록하지 않는다.

자가 회복·아군 회복을 포함해 실제로 회복시킨 양, 새로 부여한 보호막, 실제 차단 성공을 시전자에게 기록한다. 과잉 치유는 제외하고 보호막은 기존보다 늘어난 양만 제공량에 포함한다. 짧은 제어로 게이지만 쌓았을 때는 차단 성공으로 세지 않으며, 실제 시전을 취소시킨 마지막 제어의 시전자에게 기록한다. 이전 제어를 넣은 영웅의 모든 기여를 배분한 통계는 아니다.

수호신/지원과 출처를 알 수 없는 관측값은 영웅 한 명에게 덮어씌우지 않고 별도 행으로 분리한다. 영웅마다 받은 피해·받은 회복·자신의 보호막 흡수·첫 전투불능 시점·초당 피해도 표시한다. 공급자의 보호막 제공량을 실제로 방지한 피해량이라고 표시하지 않는다. 종합 MVP나 딜만으로 좋은 영웅을 선정하는 순위는 없다.

**레이드는 보스가 회복한 HP를 다시 깎은 피해도 실제 피해에 포함한다.** 심연의 개체별 최저 HP를 이용한 중복 제외 점수와 다른 지표임을 화면에 명시했다. 통계는 보상/전투 판정/강화에 사용하지 않는다.

## 3. 최근 기록과 비교

`user://raid_contribution_v1.json`에 기기 전체 최근 12회(양 진영 합계)를 보관하며 화면에서는 현재 진영만 필터링한다. 유효한 직전 결과는 저장 실패 시 실행 중 메모리에도 남긴다. 보상 세이브와 분리된 선택적 분석 파일이고 실패가 게임 보상을 되돌리거나 중복 지급하지 않는다.

레코드·문자열·배열·숫자 범위와 파일 크기(256 KiB)를 제한하고 잘못된 JSON·다른 진영 영웅·유한하지 않은 수치를 거부한다. 임시 파일을 쓰고 닫은 뒤 교체한다. 분석 파일 저장 실패를 화면에서 알리며, 저장장치가 계속 실패하면 앱 종료 후 새 분석 기록은 남지 않을 수 있다. 서버 보안이나 전원 차단 무손실을 보증하지 않는다.

같은 보스/진영/규칙/종료 결과/시작 자동 설정의 이전 기록에 대해 초당 피해·생존 변화만 안내한다. 레벨·장비·편성·중간 설정 변경·수동 입력을 통제하지 않으므로 순수 성능 실험이라고 해석하지 않도록 명시한다. 취소 기록은 비교에서 제외한다. 기존 일일/탑/심연 분석의 메모리 보관 방식은 변경하지 않았다.

두 소프트웨어 OpenGL 실행에는 VSync 변경 미지원 경고가 각각1개 있다. 가상 화면은 오디오 Dummy로 실행했으므로 스피커 청취 검사가 아니다. 엔진 결과의 스크립트·씬 335개와 화면 검사의 스크립트 해시를 최종 작업본에서 다시 대조했다.


새 레이드 실전 검사는 양 진영에서 Lv.60으로 설정한 10인 편성으로 보스 3종씩, Lv.1에서 시작하는 탱커/서포터/컨트롤러 3인 편성으로 광산·숲 보스 2종씩 실행했다. **합계 10회 모두 자연 전투로 끝났으며** 적 HP를 없애거나 강제 승리하지 않았다. 다음 보스로 갈 때 직전 보상에 따른 성장 변화는 유지한다. 독립 관찰 호스트의 실제 HP 감소/실제 치유와 보고서를 대조했고, 갑주·수정핵·치유가 실제로 발생했는지도 검사했다. 전체 조합·신규 계정 성장 과정 검증은 아니다.

진영전은 두 진영에서 실제 권한 명령을 통해 아군 요새로 행군한 뒤 정비했다. 시험에서는 권한 시계를 앞당겨 도착을 검사했으며 현실 시간 행군을 모두 기다린 시험이나 온라인 서버 시험은 아니다. 정확한 비용 차감·HP 비율·피로·중복 명령·오래된 견적·등록 해제·다른 아군 보존을 검사했다. 기존 월드 내보내기/불러오기를 실제 JSON 파일 저장·복원과 연결해 군량·부상·위치 보존도 확인했다.

독립 규칙/정산 시험의 가상 HP·명령 입력을 자연 AI 전투로 세지 않는다. 헤드리스 검사와 Linux 소프트웨어 OpenGL 화면 확인은 Android 터치/FPS/발열/메모리/진동/음원 청취를 대신하지 않는다.

## 5. 발견한 문제와 수정 이력

1. 새 정비 콜백이 이미 해제된 확인창 객체를 타입 지정 인수로 받으면, 유효성 검사 전에 Godot 타입 오류가 발생했다. 콜백 인수의 객체 타입 제한을 없애고 먼저 유효성·현재 창·삭제 대기를 검사하도록 수정했다. 초기 실패 로그는 보존했다.
2. 새 레이드 관찰기에서 `get_meta(key, null)`을 쓰면 레이드 기록이 없는 일반 사냥에서 오류 로그가 발생했다. 최종 회귀의 일일 던전이 이 문제를 발견했다. `has_meta`를 먼저 확인하도록 생산 코드를 고치고, 비레이드 관찰 전용 검사를 추가한 뒤 전체 엔진/집중 검사를 재실행했다. 실패한 첫 전체 실행은 중단/수정으로 기록하며 성공에 합산하지 않는다.
3. 과거 V75/V76 시험은 이미 v83-5에서 중첩된 화면으로 옮겨진 레이드 시각 노드를 옛 경로에서 찾았다. 현재 실제 노드 위치·참조로 시험을 고치고 기존 이펙트 조건은 유지했다. V64/V75/V76 종료 시 오디오 종료·노드 해제를 기다리도록 시험 정리 절차를 보완했다. 생산 그래픽 파일이나 전투 수치로 시험을 억지로 통과시키지 않았다.
4. 이전 주둔 제거 함수는 집결까지 지우는 함수가 아니므로, 정비 명령에 해당 부대의 집결 참가 제거를 명시적으로 연결했다. 다른 아군 참가와 지휘 승계는 남긴다.

## 6. 보존과 재현

기존 이미지 284개(게임 280개와 이전 기록용 4개), 음원 24개는 SHA-256 동일하다. 새로운 이미지·음원·폰트 파일이 없고 영웅 로스터·기본 전투 규칙·장비·수호신·레이드 설계/전장·일반 사냥 제어·게임 저장 스키마는 보존했다. 저장 버전은 36이며 새 분석 파일은 자체 버전 1이다. **현장 정비는 의도적으로 군량과 진영전 부상·피로에 영향을 주는 신규 게임 규칙**이므로 모든 게임 균형이 불변이라고 말하지 않는다.

```sh
python3 tools/run_v83_6_runtime_checks.py \
  --godot /path/to/Godot_v4.7.2-stable_linux.x86_64 \
  --workers 3 --timeout 600 --output /tmp/v83-6-results.json
python3 tools/static_validate.py
```

기존 원본/플레이어 저장 대신 임시 프로젝트와 분리 사용자 데이터에서 검사한다. 이번 증분 패치는 깨끗한 v83-5 전용이다. v83-3 전체본에는 기존 v83-4, v83-5 패치를 먼저 적용해야 한다. 다른 누적 패치를 중복 적용하지 말고 기존 저장을 백업한다. 새 게임 ZIP은 없다.

증분 패치 복원 결과와 SHA-256은 외부 `v83-6-progress.md` / `reconstruction.json`에 기록한다.
