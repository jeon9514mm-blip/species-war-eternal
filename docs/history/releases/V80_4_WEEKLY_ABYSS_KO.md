# v80-4 주간 심연 실전 연결 — 개발 작업본

**상태: 소스 구현 / Godot 엔진 실행 미검증. v80 전체 완료 또는 v81~v85 완료가 아님.**

## 기준과 범위

v79 전체 분할 압축의 CRC를 검사해 복원한 후, 마지막으로 전달한 `v80_3_work/species-war-eternal-v79-to-v80-3-WIP.patch`를 fuzz 없이 적용했다. 부모 패치 SHA-256은 `8a434c785600ff8640a3d823a9a131fc719ca691bc366a4406481fcdba481d7b`다. 서로 다른 과거 v80-2 작업본을 섞지 않았다.

일일 던전 3모드·소탕과 무한탑 실전 연결을 보존하고, 이번에는 주간 심연의 전투력 즉시 판정을 공통 ChallengeBattleDirector 경로로 교체했다. 새 그래픽이나 UI 테마를 제작하지 않았다.

## 전투와 점수

- 90 **게임 내 전투 초** 동안 기존 이동·영웅 공격·스킬·수호신 처리를 실행한다. 일시정지/앱 중단과 기존 1~2배속을 따른다. 항상 현실 시간 90초라는 의미가 아니다.
- 기존 철갑 두더지 에셋을 사용하는 정예 우두머리 1마리를 생성한다. 처치하면 다음 우두머리를 생성하고 제한시간까지 계속한다. 신규 레이드 보스 외형·고유 장판을 만든 것이 아니다.
- 주간 키에 따라 최대 HP +25% / 공격 +20% / 공격 속도 +20%가 3주 순환한다. 같은 주의 각 시도와 다음 개체는 같은 수치를 사용한다. 권장 전투력으로 승리나 점수를 만들지 않는다.
- 실제 `_damage_enemy`가 적용한 HP 감소 직후 점수를 집계한다. 남은 HP를 넘는 과잉 피해는 점수에 더하지 않는다. 개체별 최저 HP를 기록해 같은 콜백 및 귀환 회복 HP를 반복 채점하지 않는다. 따라서 재생 HP를 포함한 모든 원시 공격량이 아니라 **개체별 실효 HP 피해**다.
- 등록되지 않은 대상, 이전 조우 토큰, 종료 후 피해, 음수 HP 입력을 거부한다. 점수는 저장 상한과 같은 1,000,000,000,000으로 제한한다.
- 90초 종료 시 생존 영웅과 실제 피해가 있어야 완료한다. 전멸/이탈/조건 변경/피해 0에는 최고 기록·보상·완료 횟수를 변경하지 않는다. 실패 화면에는 그 시도 피해량을 표시할 수 있지만 최고 기록에 합산하지 않는다.

현재 HP/공격/무리 배치는 **초기 튜닝값**이며 초보 파티 난이도·실제 완주 가능성은 미검증이다. 온라인 랭킹과 서버 권한은 구현하지 않았다.

## 정산·저장·화면

기존 주 5회 완료 한도를 유지했다. 완료 회차별 보상은 아래와 같다.

| 완료 회차 | 골드 | 젬 | 영웅 경험치 |
|---|---:|---:|---:|
| 1 | 1,600 | 18 | 450 |
| 2 | 2,000 | 21 | 550 |
| 3 | 2,400 | 24 | 650 |
| 4 | 2,800 | 27 | 750 |
| 5 | 3,200 | 30 | 850 |

전투 중 일반 사냥 보상/드롭/스테이지, 일일 던전 횟수, 무한탑 기록, 레이드 보상은 증가시키지 않는다. 승리 영수증을 한 번 소비한 뒤 기록·재화를 함께 저장한다. 입장 주간·시도 횟수·최고점·진영·지역·영웅 ID·세션 일련번호를 재검사한다. 이전 버튼/세션 콜백으로 다음 회차를 정산하지 않도록 했다. 로컬 중복 방어이며 서버 보안이나 저장장치 오류 시 완전한 원자성을 보증하지 않는다.

**저장 버전은 33 → 34다.** 기존 전투력 기반 최고점은 `weekly_trial_legacy_best`와 `weekly_trial_legacy_week`로 보관하고 새 실제 피해 최고점은 0부터 시작한다. `weekly_trial_score_version=1`로 재로드 때 중복 이전을 막는다. 기존 주간 사용 횟수와 지갑, 일일 소탕 해금, 탑 기록은 유지한다. 이전 v79/v80-3에서 새 저장 파일을 사용하지 말고 원래 저장 파일을 보관해야 한다. 실제 엔진 저장 이전/복원 검증은 남아 있다.

세로형 및 기존 화면의 주간 입장 콜백이 전투 시작 직후 목록을 다시 열어 취소하지 않도록 고쳤다. 기존 레이아웃에서 주간 변칙·실제 피해·90초 목표·과거 점수 보관 안내만 연결했다.

## 공격 속도 의미 점검

기존 `attack_speed_mult`는 실제로 공격 **간격**에 곱하는 값이다. 여기에 1.2를 곱하면 오히려 느려진다. 주간 효과를 `challenge_attack_rate`로 분리해 기존 간격을 1.2로 나누도록 연결했다. 기존 정예 광폭화/귀환의 간격 초기화에도 주간 효과가 남는다. 일반 사냥과 다른 도전은 기본값 1.0을 사용하므로 이 추가 계수로 바뀌지 않는다.

기존 V11/V51/V56 테스트의 즉시 정산 기대도 실제 전투 완료 대기로 교체했다. 기존 일일·탑 소스 검사에서 저장 버전과 공통 UI 콜백 변경을 반영했으며 검사항목을 제거해 통과시킨 것이 아니다.

일일/탑 규칙·정산 파일, 영웅 카탈로그, 장비 규칙, 수호신 카탈로그, 레이드 설계/전장, AutoHuntController, RoamingHuntDirector, project.godot은 v80-3와 동일하다. 공통 Director/Session, Main의 주간 경로·실제 피해 훅·공격 간격 계수, 저장/화면/테스트는 변경했다.

## 엔진 확보와 다음 단계

공식 Linux 4.7.2 다운로드 페이지와 명령행 문서는 웹에서 확인했다. 컨테이너 직접 다운로드는 DNS 실패였고, 별도 다운로드 도구도 바이너리를 가져오지 못했다. 실행 파일을 확보했다고 기록하지 않았다.

`ENGINE_TESTING_KO.md`에 필요한 Linux x86_64 표준 실행 파일과 12개 테스트 실행 방법을 정리했다. 현재 `checks/runtime.json`은 실행 0개/blocked다. 테스트 도구는 원본 대신 임시 프로젝트 사본과 별도 사용자 데이터를 사용하고, 오류 로그·시간 초과·완료 표식 누락을 실패로 기록하도록 보강했다.

다음 우선순위는 Godot 4.7.2로 임포트·12개 집중 테스트를 실행하고 실제 전투/저장/UI 오류를 수정하는 것이다. **엔진 검증 없이 v80을 완료로 표시하거나 v81~v85 완료로 올리지 않는다.** 배포 ZIP은 만들지 않았다.
