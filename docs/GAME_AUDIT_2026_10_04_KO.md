# 전체 게임 점검과 비교 게임에서 가져올 개선점

기준은 `4751bb2151fa74ed90773dd7f2ee3c581855b95f`다. 복원한 그림 카드·아이콘 메뉴를 유지한 상태에서 코드, 실제 입력 회귀 검사, 보관함 생성과 첫 레이드 준비 상태를 확인했다. 이 작업은 점검과 제안이며 운영 게임의 수치·메뉴·저장 형식은 변경하지 않았다.

### 실제 측정에서 구분해야 할 점

보관함 단독 재측정에서는 50개 생성에 약 1.59초, 500개에 약 13.78초가 들었다. 전체 파싱 검사와 동시에 실행한 1,900개 조건은 약 66.45초였다. **headless Linux VM의 특정 구성에서 측정한 동기 생성 시간**이며 휴대폰의 지연 시간이나 FPS가 아니다. 잠금된 동일 장비의 복사본으로 항목 수의 영향을 비교했다. UI 노드 수는 장비 옵션 수에 따라 달라질 수 있다. 병렬 검사 영향을 줄인 500개 재측정에서도 지연이 재현됐으므로 페이지 처리부터 하는 근거는 충분하다.

500개 조건에서 수령 전후 스크롤 위치는 모두 2,000으로 유지됐다. 스크롤 초기화를 결함으로 보고하지 않는다. 예시 1,900개 상태의 저장 직렬화 크기는 약 594KB로 8MiB 상한보다 작았다. 이번 지연을 저장 크기 초과로 설명하지 않는다.

길드·실시간 PvP·생활 스킬을 한꺼번에 늘리기보다 **보관함 성능 → 상황별 다음 행동 → 강화 비용 예고 → 새 영웅 시험과 전술 설정** 순서를 권한다. 콘텐츠 확대는 그 뒤 장기 소비처와 함께 설계한다. 기존 30일 모델에서 장비 +10 이후 골드가 약 555만~632만 남는 것은 별도 경제 설계 항목이며, 다른 게임의 수치를 그대로 복사할 근거는 없다.

## 검사 결과와 남은 범위

- `scripts/**/*.gd`·`tools/**/*.gd` 파싱 검사 **448/448개 통과**.
- 선정한 기존 회귀 **24종 중 23종 통과**. 숫자 집계 가능한 통과 검사는 **5,496항목**이며 카운터 없는 전술 검사 1종도 통과했다.
- 사냥 상태 유지, 터치 스크롤, 저장 복구, 독립 AI, 레이드 터치·선택, 프리셋, 소탕, 무한탑·주간 전투, 분석 화면과 앱 중단·복귀를 포함했다.
- 구형 `V65GuardianSmokeTest`는 **24/25항목**으로 실패했다. 예상값 계산에서 현재의 미측정 편성 속도 제한을 빠뜨린 것이 원인이다. 현재 정책에 맞춘 별도 진단은 **25/25 통과**, 예상·실제 골드 3,559와 XP 2,237이 일치했다. 원본 검사 실패를 통과로 바꾸어 집계하지 않았다. 후속 변경에서 원본 검사 기준을 갱신할 필요가 있다.
- 실행 엔진은 **Godot 4.6.3**이다. 프로젝트 목표 4.7.2·Android 실기기·발열·배터리·메모리·장시간 실제 플레이는 이번 검사 범위 밖이다. 이전 30일 경제 결과를 인용했으며 이번에는 30일 모델을 새로 실행하지 않았다.

원자료는 [검사 기록](../checks/game-audit-2026-10-04/validation.json), [파싱 기록](../checks/game-audit-2026-10-04/parse.json), [보관함·레이드 관찰](../checks/game-audit-2026-10-04/observations.json), [보관함 단독 재측정](../checks/game-audit-2026-10-04/quick-observations.json), [공식 비교 출처](../checks/game-audit-2026-10-04/comparison-sources.json)에 있다. 진단 코드도 같은 디렉터리에 보존한다.

프로젝트 루트에서 진단을 재현할 때는 기존 저장과 분리된 폐기 가능한 경로를 지정한다. 진단 JSON은 이번 검사 디렉터리에 갱신된다. 전체 보관함 진단은 오래 걸릴 수 있으므로 먼저 아래 단독 50·500개 조건을 사용한다.

```bash
XDG_DATA_HOME="$audit_dir/data" XDG_CONFIG_HOME="$audit_dir/config" XDG_CACHE_HOME="$audit_dir/cache" \

  godot --headless --path . --script checks/game-audit-2026-10-04/GuardianPolicyProbe.gd
```

## 다음 변경 때 이어서 점검할 기준

기능을 바꿀 때 사냥 HP·쿨다운·무리 상태 유지, 터치 후 드래그의 오실행, 중복 보상·소비, 저장 실패 복구와 해당 화면의 동선을 다시 검사한다. 장비 획득·경제를 바꾸면 200칸 경계·보호 보관함 누적·7일/30일 모델을 확인한다. 전투·표시를 바꾸면 최대 편성·최대 적 수와 실제 휴대폰의 20~30분 플레이를 확인한다. 확인한 결함, 현재 정책과 맞지 않는 구형 검사, 제안 단계의 기능을 각각 기록하고 실제 적용 여부를 남긴다.

이 문서는 이번 점검 결과다. 예약된 자동 스캔이나 상시 백그라운드 실행을 설정한 것은 아니다.
