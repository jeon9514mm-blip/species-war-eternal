# v80-3 무한탑 실제 전투 연결 — 개발 기록

**상태: 소스 반영 및 정적·문법 검사 수행. Godot 실행/타입 검사/기기 테스트 미실행. 정식 완료본이 아닌 WIP.**

## 기준본과 이번 범위

마지막 전체 전달본인 v79 분할 압축의 CRC를 검사하고 복원했다. 그 위에 대화의 **`v80_2_work/species-war-eternal-v79-to-v80-2-WIP.patch`**를 적용했다. 같은 파일명이었던 다른 경로의 과거 패치와 혼합하지 않았다.

일일 던전 3유형·직접 클리어 소탕이 들어 있는 최종 v80-2를 보존하고, 무한탑 전투 연결만 다음 단계로 추가했다. 현재 상태는 프로젝트의 `DEVELOPMENT_STATUS.json`에도 기록했다.

## 1. 무한탑의 전투 흐름

- 기존 전투력 비교 → 즉시 층 상승·보상 지급을 제거하고 **입장 → 실제 이동/공격/스킬 → 적 무리 전부 격파 → 1회 정산**으로 연결했다.
- 일반 층: 90초 안에 4마리씩 2개 무리 격파.
- 5층 단위: 일반 2개 무리 이후 **정예 수문장 1마리 + 호위 2마리**가 있는 마지막 무리까지, 총 3개 무리 격파.
- 층별로 전열 돌파 / 후열 경계 / 원거리 제압 구성을 순환한다. 사용한 적은 기존 종족 카탈로그와 그래픽의 몬스터다. 새로운 보스 그림이나 레이드 패턴을 제작한 것이 아니다.
- 권장 전투력은 정보로 남기되 미달이어도 출전 가능하다. 권장 전투력만 넘었다고 자동 승리하지 않는다.
- 제한시간은 기존 전투 속도·일시정지를 따르는 게임 내 전투 시간이다.
- 적 HP·공격력은 층에 따라 상승한다. **현 수치는 초기 튜닝값이며 실제 완주·난이도·길찾기는 미검증이다.**

## 2. 기존 보상·저장 유지와 중복 방어

클리어한 층을 F라고 할 때 기존 보상은 `골드 = 250 + 90 × F`, `젬 = 2 + floor(F / 5)`로 유지했다. 예: 1층 340골드/2젬, 5층 700골드/3젬, 10층 1,150골드/4젬.

승리 영수증을 한 번 소비한 뒤에만 최고층·다음 층·골드·젬을 변경하고, 한 저장 스냅샷에 담는다. 전투력·입장 버튼·중간 무리 처치만으로 보상은 주지 않는다. 일일 던전/주간 심연 횟수, 소탕 해금, 일반 사냥 장비·스테이지·보상에는 연결하지 않았다.

입장 층·최고층·진영·지역·영웅 ID 목록·전투 일련번호를 다시 검사한다. 전멸·시간 초과·이탈·조건 변경에는 보상과 층 상승을 적용하지 않는다. 탑은 일일 콘텐츠가 아니므로 날짜 변경만으로 실패하지는 않는다.

오래된 버튼 콜백에는 이전 층의 스냅샷을 묶어 다음 층을 연속으로 시작시키지 않도록 했다. 종료한 전투가 새 전투를 정산하거나 닫지 못하도록 현재 세션의 객체도 확인한다.

**저장 버전은 v80-2의 33을 그대로 사용한다.** 기존 `tower_floor`/`tower_best_floor` 저장 필드를 유지하고 과거 탑 기록을 초기화하지 않는다. 탑 기록을 새로 진영별로 분리한 것은 아니다.

기존 저장 검사에서 다음 층을 10,000까지 저장하므로, 9,999층까지 정산 후 다음 층 10,000을 종료 표식으로 남긴다. 10,000층 보상 후 저장이 잘려 같은 층 보상을 반복 획득하는 경계 문제를 차단했다. **9,999층을 모두 실제 플레이 검증했다는 뜻은 아니다.**

이는 로컬 중복 처리 방어다. 서버 권한이나 저장장치 실패 시 완전한 원자성까지 검증한 것은 아니다.

## 3. 화면 연결 수정

세로형 화면과 남아 있는 기존 화면 양쪽의 탑 입장 콜백을 수정했다. 이전에는 입장 성공 직후 목록을 다시 열도록 되어 있어, 실제 전투로 전환하면 시작 즉시 취소될 수 있었다. 이제 탑은 전투 화면에 남고, 결과 정산 후 탑 탭으로 돌아간다.

기존 HUD의 층 이름·목표 무리 수·남은 시간 표시를 재사용한다. 입장 화면은 실제 전투 목표와 기존 보상을 표시한다. 이미지/색상 테마/하단 메뉴 레이아웃을 새로 디자인하지 않았다.

실행 가능한 Godot를 확보하지 못했다. 컨테이너의 공식 사이트 접속은 DNS 오류였고, 웹에서 확인한 공식 바이너리는 다운로드 도구로 가져오지 못했다. 엔진이 없으면 실패 상태/실행 0개로 보고하는 전용 실행 도구를 추가했다. 정적 검사를 엔진 실행 결과로 대체하지 않는다.

### 신규 Godot 테스트 — 작성만 완료, 미실행

1. `V80TowerRulesSmokeTest.gd`: 층/무리/보상 규칙, 승리 영수증, 중복·타임아웃, 저장 상한.
2. `V80TowerSettlementSmokeTest.gd`: 작은 테스트 호스트로 정산·진영/편성 변경·중복/오래된 세션·실제 SaveStore 읽기/쓰기 코드를 검사하도록 작성. **이 단위 테스트의 가상 전투 관찰값을 실제 AI 전투 테스트로 세지 않는다.**
3. `V80TowerBattleSmokeTest.gd`: 실제 PortraitMain 씬과 기존 영웅 AI로 1·5·6층을 진행하고 UI 입장/정예 생성/보상/필드 보상 분리/이탈을 검사하도록 작성. 적 HP를 0으로 바꾸거나 강제 승리하는 코드는 넣지 않았다. 테스트 파티는 레벨 60의 3영웅이며 기본 신규 유저 난이도 검증이 아니다.

기존 V9/V56 테스트의 즉시 승리 가정도 실제 전투 완료 대기로 교체했다. 일일 소스 검사에서 화면 복귀·문맥 검사 호출 경로가 확장된 부분은 새 코드에 맞게 수정하고 기존 검사항목은 유지했다.

## 5. 보존 사항

v80-2와 비교해 `DailyDungeonBattleRules`, `DailyDungeonProgress`, `SaveStore`, `SaveValidation`, 영웅 로스터/전투 규칙, 장비 규칙, 수호신 카탈로그, 레이드 설계/전장, `project.godot`은 원문을 유지했다. `Main.gd`의 기존 함수 중 변경은 `_challenge_tower`뿐이며 탑 입장 문맥/오류 조회 래퍼 2개를 추가했다. 공통 도전 전투 Director는 모드별 생성·정산 분기를 확장했다.

주간 심연의 기존 즉시 판정 함수는 이번 단계에서 변경하지 않았다. 새 개발 상태 문서/테스트/도구 외에 원본 파일 삭제는 없다.

## 6. 재현 방법

```sh
python3 tools/static_validate.py
python3 tools/godot47_compat_scan.py
python3 tools/validate_v80_daily_integration.py
python3 tools/validate_v80_2_daily_modes.py
python3 tools/validate_v80_3_tower.py
PYTHONDONTWRITEBYTECODE=1 python3 tools/gdsyntax/check.py .

# 실행 파일이 있어야 실제 검사 진행. 없으면 exit 2, 실행 개수 0.
python3 tools/run_v80_runtime_checks.py --godot /path/to/godot --output /tmp/v80-runtime.json
```

문법 검사는 Python `lark`와 `regex`가 필요하다. 실행 도구는 별도의 임시 사용자 데이터 폴더로 일일+탑 테스트 8개를 호출하고, 임포트 오류·스크립트 오류·시간 초과를 실패로 기록하도록 작성했다. 실제 사용한 엔진 결과는 `checks/runtime.json`의 blocked/0개다.

명령 옵션의 공식 참고 자료:
- Godot command line: https://docs.godotengine.org/en/stable/tutorials/editor/command_line_tutorial.html
- Godot Linux downloads: https://godotengine.org/download/linux/
