# Godot UI 구성의 Unity 이식 — 2026-10-09

사용자의 최신 요청에 따라 영웅 화면과 메뉴는 보존된 Godot 소스의 구성과 원본 그래픽을 기준으로 Unity UI Toolkit에 옮겼다. Unity에서 이미 연결된 성장·편성·저장·전투 명령을 사용한다. 이번 작업은 소스 구현과 정적 검사까지 완료했으며 Unity 컴파일·실행 검증은 남아 있다.

## 변경한 화면

| 화면 | 변경 내용 |
| --- | --- |
| 사냥 HUD | 상단 스테이지·재화·편성/정지/속도/관리, 하단 영웅 10칸과 5개 메뉴. 영웅 원본 초상, 레벨·상태·HP·각성 게이지를 표시한다. 수동 스킬 연계는 펼침/접힘으로 전환한다. |
| 영웅 | 왼쪽 목록, 가운데 큰 원본 초상, 오른쪽 정보와 성장·스킬·장비·승급 탭, 하단 편성 슬롯. 선택 탭과 스크롤 위치를 유지하고 기존 연구·강화·승급·장착 명령에 연결한다. |
| 편성 | 왼쪽 5×2 슬롯·진형·프리셋 3개와 오른쪽 영웅 카드·역할/정렬/검색. 상세 확인 뒤 편성 초안으로 돌아올 수 있다. 확정한 편성은 기존 규칙대로 다음 적 무리에 적용된다. |
| 전체 메뉴 | Godot의 오른쪽 서랍, 대표 카드 6개와 6×2 아이콘, 설정 바. 원정 캠프 그림은 원본 PNG를 그대로 복사했다. |

| 시작 화면 | 두 진영 카드와 큰 초상, 기존 기록 가져오기 접기, 공통 테마를 적용했다. |

영웅 30명·스킬 정의·저장 형식·전투 수치의 교체는 포함하지 않는다. 영웅 그림은 기존 카탈로그/스타일 오버라이드를 사용한다.

## 메뉴와 동작 범위

영웅·편성·장비·소환·수호신·펫·연구·보상·보관함·레이드·가이드·설정은 기존 Unity 동작에 연결했다. 효과음과 스킬 효과 표시 설정은 저장되며, 전투 판정이나 레이드 경고를 끄지 않는다. 저장 실패·레이드 중 편성 변경·다른 진영 접근 제한을 유지한다.

Godot에만 있고 아직 Unity 동작이 없는 종족 전쟁·목표·거래소와 성장 메뉴 일부 던전은 `이관 중`으로 비활성화했다. 버튼만 보여 주면서 작동한다고 주장하지 않는다. 완성된 콘텐츠 이식이나 신규 APK 배포는 이번 범위에 포함되지 않는다.

- 기존 네이티브 입력 검사 소스의 메뉴·탭·편성·관리 경로를 새 UI 이름에 맞췄다. 입력 자체는 실제 Input System 누름/놓기 방식을 유지했다.
- **Unity 에디터와 C# 컴파일러가 이 작업 환경에 없어 타입 검사·컴파일·실제 클릭·화면 배치·기기 테스트는 실행하지 못했다.** 성능 측정도 하지 않았다.

기존 검사에는 이번 UI와 별개의 오래된 가정이 남아 있다. `NativeInputAcceptance`의 제거된 긴급 회피 버튼 검사와 기본 `StandaloneGameAcceptance`의 몬스터 4종 기대값은 현재 조이스틱/7종 검사와 맞지 않는다. 실제 실행 전 해당 검사 범위를 정리해야 한다. [정적 검사 원본](../../checks/unity-ui-overhaul-2026-10-09/source-validation.json)에 구체적인 범위를 기록했다.

다음 실행 검수에서는 Unity 임포트·컴파일 후 별도 검수 프로필로 사냥→영웅→성장/장비→편성→메뉴→레이드→복귀를 확인한다. 16:9 및 좁은 가로 화면에서 스크롤·입력 차단·10칸 표시·저장 후 재시작을 확인해야 한다.
