# 왕립 수림 화면 UI 한정 업데이트

사용자의 화면 UI만 GitHub에 올리라는 요청에 따라 원격 기본 브랜치 `jeon9514mm-blip/species-war-eternal`의 `2c1c8fc`에서 UI 변경만 분리했다. 로컬 미게시 그래픽 커밋 `37d52ed`, `4dde77d`와 이후 모델·텍스처 변경은 포함하지 않는다.

## 반영 범위

- 개발 사냥 HUD의 금색 프레임·어두운 패널·스테이지/재화 표시, 원형 영웅 슬롯·스킬/이동 조작계·체력/각성 표시·배율 버튼.
- UI Toolkit Painter2D로 직접 그리는 `RoyalHudSurface`와 `RoyalHunt.uss`. 화면 전체에 시안 이미지를 덧붙이지 않는다.
- 하단 메뉴 `사냥 · 영웅 · 레이드 · 던전 · 가방`과 선택 강조.
- 개발 HUD의 영웅/스킬·레이드 패턴 정보·가방 정보 패널. 메뉴를 열 때 전투를 일시정지하고 닫을 때 이전 상태를 복구한다.
- 기존 실제 플레이 UI의 동일한 하단 순서와 기존 영웅 관리·레이드 선택/입장·성장/던전 허브·가방 연결. 종전 `도전` 경로는 `레이드`의 호환 별칭으로 유지하며 전체 메뉴는 관리 화면에서 접근한다.

개발 HUD의 레이드 메뉴는 패턴 정보 화면이고 던전 전투는 준비 상태를 표시한다. 기존 플레이 화면은 이미 있는 기능으로 이동한다. 새로운 던전 전투를 구현했다고 보고하지 않는다.

## 유지 범위

영웅·몬스터 모델과 텍스처, 외형 불러오기 코드, 맵·카메라·조명, 사냥/레이드 전투 규칙, 패키지와 프로젝트 설정은 원격 기준 버전을 유지한다. 루네아 추가 편성·픽셀 스프라이트·픽셀 3D 모델·Rapid Assets 설치/생성/인증·새 레온하르트/미라 모델은 업로드하지 않는다. APK도 갱신하지 않는다.

## 확인

영웅 그래픽 변경이 빠진 별도 checkout을 Unity 6000.6.4f1에서 컴파일하고 실행했다. 실제 Game view 1600×900에서 사냥·영웅·레이드·던전·가방 다섯 메뉴의 화면을 확인했다. `git diff --check`와 업로드 파일 허용 목록 검사도 통과했다. 영웅·그래픽 리소스·장면·패키지·프로젝트 설정은 기준 커밋과 같음을 대조했다.

첫 실행은 Git에서 제외된 원본 가져오기 자료가 없어 진행되지 않았다. 기존 가져오기 자료를 별도 checkout에만 복구하고 hero-catalog를 기준 버전과 SHA 대조한 뒤 다시 실행했다. UI 컴파일 오류는 없었고 다섯 화면이 생성됐다. 촬영 보고서의 completed는 기존 Unity 검색 인덱스 예외 때문에 false다. 에디터 로그의 기존 URP 리소스 오류와 기준 버전 `AureliaVolumeActor` 생성자 오류도 이번 UI 변경과 분리해 남겼다. 전체 게임 오류나 성능 검사 통과로 보고하지 않는다.

촬영용 기존 헬퍼·캡처·로그·가져오기 자료는 GitHub에 포함하지 않는다. 프레임 벤치마크나 APK 실기기 검수는 이번 범위가 아니다.

## 진영전 하단 버튼 추가

사용자의 추가 요청으로 하단 순서를 `사냥 · 영웅 · 레이드 · 던전 · 진영전 · 가방`으로 변경했다. 개발 사냥 HUD와 기존 실제 플레이 화면 모두에 적용하고 양 진영 깃발 아이콘을 추가했다. 전체 메뉴의 종의 전쟁 카드도 같은 진영전 화면으로 연결했다.

진영전 화면은 기존 저장의 `selected_faction`과 `faction_war` 필드를 읽어 보유 영토·군량·명예·피로·전투 기록 수를 표시한다. 기존 기록이 없으면 빈 상태를 표시한다. 기록을 초기화하거나 점령·보상을 만들어 내지 않는다. Godot의 전투·행군·점령·시즌·서버 권한 기능은 아직 별도 Unity 이식 대상이다. 진영전 버튼과 저장 정보 화면 연결을 전체 진영전 전투 구현 완료로 보고하지 않는다.

동일한 UI 한정 checkout을 다시 컴파일하고 실제 Unity Game view에서 여섯 메뉴 화면을 확인했다. 에디터 검색 인덱스 예외는 종전과 같으며 전체 검사 통과나 휴대폰 APK 확인을 뜻하지 않는다. 영웅 그래픽·맵·전투 규칙은 이번 UI 추가에서도 유지한다.
