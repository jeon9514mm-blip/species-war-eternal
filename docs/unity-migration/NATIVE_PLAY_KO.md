# Unity 실행과 저장

Unity 6000.6.4f1에서 `Unity/`를 열고 `Assets/Scenes/Eternal.unity`를 Play합니다. 기본 빌드 장면도 이 파일입니다. 기존 `HuntingReview.unity`는 별도 임시 검수 장면으로 보존합니다.

아우렐리아·녹스페라의 영웅 15명 중 10명으로 시작합니다. 새 원정대는 Lv1, 골드 500, 젬 100입니다. 영웅·스킬 ID와 성장 기록을 유지합니다. 오르윈·카엘룸·카이렌은 각자 다른 새 스타일 원화를 사용합니다. 원정대 메뉴에서 1~10명의 순서와 진형을 정하면 다음 무리부터 적용합니다. 작은 원형 초상과 앞으로·뒤로 버튼으로 순서를 바꾸고 편성 3개를 저장·불러올 수 있습니다. 완료한 무리의 경험치는 해당 무리와 싸운 기존 원정대에게 먼저 배분합니다.

사냥 무리 격파 시 해당 분위기의 골드·경험치·몬스터 장비 획득을 자동 정산합니다. 성장·강화·장착·소환·스킬 연계·편성도 같은 기록을 사용합니다. 실제 레이드는 현재 편성·레벨·장비·연구 능력치를 사용합니다. 패턴 훈련은 Lv50 임시 원정대를 사용하며 보상을 주지 않습니다. 실제 레이드 승리 보상은 이번 Unity 규칙으로 지역 사냥 골드의 20배, 경험치의 10배입니다. 도전 번호와 지역을 묶어 한 번만 정산합니다. 기존 Godot 레이드 보상 서비스 전체와 동일하다는 의미는 아닙니다.

기록은 Unity의 `Application.persistentDataPath/UnityProfiles-v1`에 진영별로 자동 저장합니다. 정상 실행은 검수용 시작 레벨이나 임시 재화로 바꾸지 않습니다. 체크섬, 원자적 파일 교체, 이전 정상 기록 백업, 손상 파일 보존, 최신 버전 덮어쓰기 방지, 동시 실행의 오래된 기록 덮어쓰기 방지를 적용했습니다. 저장 실패 시 전투를 일시정지하고 원정대 메뉴의 **다시 저장**으로 동일 기록만 재시도합니다. 보상을 다시 지급하지 않습니다.

시작 화면의 **기존 기록 파일**에 Godot 저장 파일 경로를 입력하고 **기록 가져오기**를 누릅니다. 지정한 원본과 그 백업·임시 파일은 읽기만 합니다. 유효한 저장본의 재화·영웅 성장·장비·연구·알 수 없는 추가 필드를 보존한 새 Unity 파일을 만듭니다. 원본의 `idle_stage`를 Unity 사냥 진행에 연결하고 지역은 스테이지 구간으로 결정합니다. `current_zone_id`는 보존하며 직접 지역을 고르는 흐름은 사용하지 않습니다. 스테이지 내부의 킬 진행, 전투 중 체력·위치·쿨다운·난수 상태와 아직 이관하지 않은 콘텐츠 진행은 완전 재현 대상이 아닙니다. 실제 사용자 저장 파일의 이행 검증은 아직 하지 않았습니다.

개발용 Windows 실행본은 Unity 빌드 명령으로 `Assets/Scenes/Eternal.unity`를 `StandaloneWindows64`로 빌드합니다. 재현 가능한 입력·두 프로세스 저장 검수는 `tools/unity/run-windows-game-review.ps1`입니다. 명시적인 개발 검수 플래그가 있어야 동작하며 프로필은 해당 빌드 폴더 안의 새 임시 디렉터리로 한정합니다. 일반 실행에는 검수 입력이 설치되지 않습니다. 실행 바이너리는 Git에 넣지 않으며 소스·장면·검수 자료를 게시합니다.

사냥터는 하나의 확장 맵입니다. 1~499 초원, 500~999 광맥, 1000~1499 달빛 숲을 사용하고 이후 500 스테이지마다 순환합니다. 기본 ×1은 멀리서 보는 전체 화면이며 작은 원형 ×1.5·×2·×3 버튼으로 같은 중심을 확대합니다. 드래그는 없습니다. [몬스터 스킬·장비 보관·맵 범위](HUNT_WORLD_CP14_KO.md)를 확인하세요. 배경의 가장자리 구조물은 원화 표현이며 별도의 입체 충돌 지형을 추가한 것은 아닙니다.

사냥 연계와 각 지역 레이드 연계는 따로 저장합니다. 레이드에서 **연계 순서**를 편집하면 해당 지역 설정만 바뀝니다. 훈련 중 편집은 해당 훈련 안에서만 적용하며, **다시 도전**도 훈련 모드를 유지합니다. 레이드 대응 안내는 현재 카운터 가능 여부와 공격 타이머·갑주·수정핵·월식 의식·약점 노출을 읽어 표시합니다. 후속 공격이 더 빨리 닿는 경우 그 대응을 먼저 보여줍니다.

사냥·레이드 왼쪽 아래 **조이스틱**을 누르고 드래그해 원정대를 직접 이동합니다. 손을 떼면 정지합니다. 사냥의 **자동 추적**, 레이드의 **추적 복귀**로 자동 이동을 다시 사용합니다. 직접 이동 중에는 자동 회피가 개입하지 않으며, 추가 무적을 주지 않습니다. 긴급 회피 버튼은 삭제했습니다. 카메라는 드래그하지 않습니다. 레이드 **산개 대형**으로 두 줄 간격을 벌릴 수도 있습니다. 상단 왼쪽 페이즈·공용 기믹 상태와 갑주 조각·수정·의식 문양이 실제 전투 집계값을 표시합니다. 표현물 자체는 별도 공격 타깃이 아닙니다. [레이드 변경과 검수 범위](RAID_PRESENTATION_CP15_KO.md)를 확인하세요. 이번 작업용 Windows 빌드는 `Unity/Builds/WindowsPlayCP15/EternalUnity.exe`이며, 이전 `WindowsPlay` 실행본과 구분합니다. 빌드 결과는 Git에 포함하지 않고 소스·검수 이미지를 게시합니다.

자동 사냥 원정대가 가까운 공통 교전 후보를 사용하고 멀리 흩어지는 이동 목표를 제한합니다. 17차에서는 공통 접근 방향을 기준으로 전열·측면·원거리·지원 경로를 선호하며 이미 공격 가능한 자리를 유지합니다. **빠른 성장**의 원형 초상으로 영웅을 선택합니다. 능력치 요약은 고정하고 장비·연구·승급 전용 탭을 사용하며, 영웅 변경과 강화 후에도 탭을 유지합니다. 레이드 **무력화 지원**은 전조 중 준비된 원래 스턴 스킬을 시전합니다. 제어 면역·거리·쿨다운·자원·행동 상태 제한을 따르며 별도 무적을 주지 않습니다. 대응 안내에 현재 준비 상태와 해당 전조 범위 안 영웅 수를 표시합니다. [17차 변경 범위와 검수](COMBAT_POLISH_CP17_KO.md)를 확인하세요. 현재 작업용 실행본은 `Unity/Builds/WindowsPlayCP17/EternalUnity.exe`입니다.

원화 스킬 모양은 기존 8종을 공유하며 120개 원본 프로필과 30명의 문양·색·타이밍을 사용합니다. 칼날·얼음·문장·잎·화살·보석·별의 일곱 강조 실루엣이 기존 이펙트에 더해집니다. 비행하는 시각적 투사체가 도착한 뒤 명중 표현을 시작하며, 원래 전투 피해 정산은 늦추지 않습니다. 투사체의 속성과 베기 방향을 구분하고 실제로 시전한 영웅·스킬을 짧게 표시합니다. 영웅마다 별도 제작한 120개 그림이나 최종 연출을 모두 완성했다는 의미는 아닙니다. 전체 콘텐츠·30명 개별 연출 검수·모바일 최종 성능은 남아 있으며 기능과 디자인을 먼저 연결하고 프레임 최적화는 마지막에 진행합니다.
