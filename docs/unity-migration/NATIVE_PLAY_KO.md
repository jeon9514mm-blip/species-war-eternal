# Unity 실행과 저장

Unity 6000.6.4f1에서 `Unity/`를 열고 `Assets/Scenes/Eternal.unity`를 Play합니다. 기본 빌드 장면도 이 파일입니다. 기존 `HuntingReview.unity`는 별도 임시 검수 장면으로 보존합니다.

아우렐리아·녹스페라의 영웅 15명 중 10명으로 시작합니다. 새 원정대는 Lv1, 골드 500, 젬 100입니다. 영웅·스킬의 원본 ID와 원화는 유지합니다. 원정대 메뉴에서 1~10명과 진형을 정하면 다음 사냥 무리부터 적용합니다. 완료한 무리의 경험치는 해당 무리와 싸운 기존 원정대에게 먼저 배분합니다.

사냥 무리 격파 시 원본 지역의 골드·경험치를 자동 정산합니다. 성장·강화·장착·소환·스킬 연계·지역 이동도 같은 기록을 사용합니다. 실제 레이드는 현재 편성·레벨·장비·연구 능력치를 사용합니다. 패턴 훈련은 Lv50 임시 원정대를 사용하며 보상을 주지 않습니다. 실제 레이드 승리 보상은 이번 Unity 규칙으로 지역 사냥 골드의 20배, 경험치의 10배입니다. 도전 번호와 지역을 묶어 한 번만 정산합니다. 기존 Godot 레이드 보상 서비스 전체와 동일하다는 의미는 아닙니다.

기록은 Unity의 `Application.persistentDataPath/UnityProfiles-v1`에 진영별로 자동 저장합니다. 정상 실행은 검수용 시작 레벨이나 임시 재화로 바꾸지 않습니다. 체크섬, 원자적 파일 교체, 이전 정상 기록 백업, 손상 파일 보존, 최신 버전 덮어쓰기 방지, 동시 실행의 오래된 기록 덮어쓰기 방지를 적용했습니다. 저장 실패 시 전투를 일시정지하고 원정대 메뉴의 **다시 저장**으로 동일 기록만 재시도합니다. 보상을 다시 지급하지 않습니다.

시작 화면의 **기존 기록 파일**에 Godot 저장 파일 경로를 입력하고 **기록 가져오기**를 누릅니다. 지정한 원본과 그 백업·임시 파일은 읽기만 합니다. 유효한 저장본의 재화·영웅 성장·장비·연구·알 수 없는 추가 필드를 보존한 새 Unity 파일을 만듭니다. 원본의 `idle_stage`와 `current_zone_id`를 Unity 사냥 진행·지역에 연결합니다. 스테이지 내부의 킬 진행, 전투 중 체력·위치·쿨다운·난수 상태와 아직 이관하지 않은 콘텐츠 진행은 완전 재현 대상이 아닙니다. 실제 사용자 저장 파일의 이행 검증은 아직 하지 않았습니다.

개발용 Windows 실행본은 Unity 빌드 명령으로 `Assets/Scenes/Eternal.unity`를 `StandaloneWindows64`로 빌드합니다. 재현 가능한 입력·두 프로세스 저장 검수는 `tools/unity/run-windows-game-review.ps1`입니다. 명시적인 개발 검수 플래그가 있어야 동작하며 프로필은 해당 빌드 폴더 안의 새 임시 디렉터리로 한정합니다. 일반 실행에는 검수 입력이 설치되지 않습니다. 실행 바이너리는 Git에 넣지 않으며 소스·장면·검수 자료를 게시합니다.

사냥터의 바닥은 현재 공통 원화 석판입니다. 지역별 몬스터·보상·레이드 맵은 나뉘며, 지역별 사냥 배경 마감·전체 콘텐츠·30명 개별 연출 검수·모바일 최종 성능은 남아 있습니다. 기능과 디자인을 먼저 연결하고 최종 문제 점검 및 프레임 최적화를 진행합니다.
