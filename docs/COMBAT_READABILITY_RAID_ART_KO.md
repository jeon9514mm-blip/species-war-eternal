# 대미지 표시·레이드 원화·최종 v28 UI·UX 개선

작업 날짜: **2026-10-07**, 엔진 **Godot 4.7.2**. 기준 소스는 `ab0d801`입니다. 실제 적용 장면은 `scenes/PortraitMain.tscn`이며 가로 전용과 기존 사냥 방식, 장비 200칸, 레이드 10배 강화 기준을 유지합니다.

## 대미지 숫자

일반 UI의 기기 글꼴 대신 **Barlow Condensed Black Italic**을 게임에 포함했습니다. 숫자만 이 글꼴을 사용하며 한국어 메뉴는 기존 글꼴을 유지합니다. 라이선스는 `assets/fonts/combat/OFL.txt`에 있습니다.

| 종류 | 표시 | 동작 |
| --- | --- | --- |
| 일반 피해 | 아이보리 숫자·어두운 외곽선 | 작은 충격 뒤 잠시 유지하고 짧게 상승 |
| 치명타 | 더 큰 금색 숫자·작은 CRITICAL 표식 | 일반 피해보다 긴 유지 |
| 영웅 피격 | 붉은색·마이너스 기호 | 피해와 별도 채널 |
| 회복 | 청록색·플러스 기호 | 조금 더 부드러운 상승 |

금액은 `1,234,567`처럼 정확한 숫자를 표시합니다. 같은 대상·같은 종류에서 **첫 표시 후 120ms 이내**의 연타만 실제 피해 합계로 묶습니다. 치명타·일반 피해·회복은 서로 합산하지 않으며 첫 시각을 기준으로 다음 묶음을 시작해 합계가 무한히 이어지지 않습니다.

표시 전체 이동 범위를 예약해 숫자끼리 겹치지 않도록 배치하고 전장 밖으로 나가지 않게 합니다. 밀집 상황에서는 표시 수를 제한하며 치명타·회복을 우선합니다. 표시가 생략돼도 실제 HP·전투 보고서·보상은 그대로입니다. 표시용 풀은 최대 40개이며 실제 동시 숫자 제한은 기존 성능 설정을 따릅니다.

사냥과 레이드는 같은 스타일과 풀을 사용합니다. 레이드의 갑주·소환 수정에 들어간 피해도 실제 처리된 수치로 표시하고, 영웅 피격·회복은 해당 영웅의 투영된 위치에 표시합니다. 렌더 코드는 난수를 뽑거나 피해를 추가하지 않습니다.

세 장은 이번 게임용으로 새로 생성한 원화입니다. 단순 메시를 쌓아 만든 환경이 아니라 **상세한 2.5D 배경 원화 + 가장자리 대기 표현 + 실제 GPU 영웅 골격·보스 + 공격 경고 + UI**로 합성합니다. 배경 속 건물 전체가 입체 모델이거나 자유 카메라로 탐색 가능한 구조는 아닙니다.

각 환경은 다른 원화를 쓰고 활성 레이드의 애셋만 로드합니다. 배경은 입력을 받지 않습니다. 기존 `RaidBattlefield`의 이동 바닥·공격 판정·카메라 투영·터치 좌표는 유지합니다. 경고와 배우가 같은 좌표 변환을 사용하며 배경 때문에 이동 공간이 막히지 않습니다. 대기 표현은 전투 준비·중지·앱 중단 시 정지하고 절전 모드에서는 움직이지 않습니다.

단계 전환 안내는 중앙의 큰 글자 대신 왼쪽의 작은 패널에 배치해 영웅·보스·경고를 덜 가립니다. 일반 사냥의 동시 타격 장식도 32개에서 12개로 제한했습니다.

## 영웅 연결과 코드 구조

30명 공통 골격의 머리 회전 중심을 얼굴 내부에서 목깃 방향으로 옮기고, 목 회전은 ±0.075rad, 손목은 ±0.065rad, 무기·보조 장비의 상대 회전은 ±0.028rad로 제한했습니다. 기존 원화·영웅 비율·21개 관절·16가지 동작·전투 타이밍은 유지합니다. 큰 목 꺾임과 손목·그립 분리감을 줄이는 보정이며, 새 원화 제작이나 모든 관절의 최종 디자인 승인 완료를 의미하지 않습니다.

대미지 표시·화면 투영·밀도 관리는 `scripts/presentation/CombatTextPresenter.gd`로 분리했습니다. 기존 기본 화면의 일반 안내 표시도 서비스로 옮기되 동작을 보존했습니다. `scripts/app/Main.gd`는 5,684줄에서 **5,661줄**로 줄었으며 다른 책임도 순차 분리가 필요합니다.

## 사용자 최종 v28 참고의 실제 구현

참고 자료는 [v27 UI·UX](https://www.meta.ai/share/a/673e2940-44f0-4c0d-be4a-9faedcd1106a)와 사용자가 최종본으로 지정한 [v28 10인 영웅 장비 UI·UX](https://www.meta.ai/share/a/eb52ac8c-c25d-48db-bf3c-f1144edf65df)입니다. 공개 ZIP 두 개를 다운로드해 README·GDScript·Theme 내용을 읽었습니다. 참고 GDScript는 주석과 `pass`인 함수로 구성되어 실제 구현이 없으며, Theme도 완전한 Godot 리소스 구조가 아닙니다. 덮어쓰는 대신 현재 운영 화면과 기존 명령에 아래 기능을 구현했습니다.

- **공통 분위기:** 숯빛 `#151A1E` 패널, 브론즈 `#C4A484` 선택·주요 버튼, 이끼색 `#A8B89E` 상승·활성 상태. 한국어의 가독성과 44px 이상의 주요 터치 영역을 유지합니다.
- **장비:** 200칸·40개씩 5페이지를 유지하며 **5열**로 변경했습니다. 전설은 브론즈, 희귀는 돌빛 청색으로 구분하고 비교 아이콘은 76px입니다. 세 부위 버튼을 모두 하단 메뉴 위에 배치합니다.
- **실시간 검색:** 0.2초 후 이름·세트·옵션을 검색합니다. 입력 필드·키보드 포커스·커서를 교체하지 않고 목록만 갱신하며 검색 결과에 맞춰 페이지를 초기화합니다. 기존 검색 버튼·Enter·상세 필터도 동작합니다.
- **정렬:** 등급·장비력·세트·옵션·최근순. 세트순은 실제 세트 이름으로 묶고 동일 세트 안에서는 기존 등급·장비력 순서를 사용합니다.
- **10인 파티:** 실제 출전 영웅의 얼굴·역할·레벨을 가로 목록에 표시합니다. 선택은 장착 대상만 바꾸며 편성·재화·장비를 변경하지 않습니다. 기억한 영웅이 화면 밖에 있으면 목록을 해당 영웅까지 스크롤합니다. 예비 영웅 선택은 기존 드롭다운에 유지합니다.
- **비교:** 장비력의 절대 차이와 기존 값 대비 증감률을 표시합니다. 퍼센트 옵션은 상대 비율 대신 **퍼센트포인트(%p)** 차이를 보여줍니다. 같은 능력치의 여러 옵션은 합산하며 실제 상한·세트 손실은 기존 비교 계산에서 표시합니다. 세트 활성 2/3개와 진행 막대도 실제 장착 데이터를 사용합니다.
- **파티 추천 장착:** 기존 추천 명령을 직접 연결했습니다. 실제 파티 전투력을 표시하며 세트까지 최적화하거나 팀 전투력이 반드시 증가한다고 보장하지 않습니다.
- **사냥·메뉴·레이드 목록:** 사냥 하단에 실제 영웅 얼굴과 5px HP 게이지를 넣었습니다. 메뉴 카드에는 원정·새 환경 원화와 기능 아이콘을 넣고 레이드 선택 카드에도 각 실제 환경 원화를 사용합니다.

참고의 가짜 스파크라인, 임의 팀 전투력 증가, 지원하지 않는 6세트·공명 규칙은 추가하지 않았습니다. 별도 3가지 가방 보기 모드·세트 프리셋·세트 최적화 알고리즘·화면 전체 블러는 이번 구현에 포함하지 않았습니다. 추가하더라도 기존 보호 장비·저장 정책과 실제 능력치에 연결해야 합니다.
