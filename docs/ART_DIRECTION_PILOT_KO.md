# 비주얼 개편 시범 01 — 레온하르트와 밝은 초원

사용자가 선택한 첫 대상은 **레온하르트 + 밝은 초원**, 캐릭터 비율은 **조금 길쭉한 4등신 안팎 SD**다. 밝은 회화풍 판타지 배경과 애니메이션풍 영웅 동작을 목표로 하되, 현재 게임의 사냥 방식은 유지한다. 본 문서는 첫 시범의 제작 기준이며 전체 영웅·맵 개편 완료 보고서가 아니다.

## 이번에 추가한 시범

현재 작업 상태는 **`prototype_pending_visual_feedback`**이다. 시작 기준은 레이드 품질 개선을 반영한 main 커밋 `eb1812d9dd28eca0f830322f2e33a01bb434a57e`다. `project.godot`와 기본 실행 장면, 운영용 게임 코드는 변경하지 않고 독립 시범 장면·자산·검증 도구를 추가한다. GitHub main 반영은 검토할 시범을 공유하는 것이며 완성 디자인을 기본 플레이에 적용한다는 뜻이 아니다.

| --- | --- |
| [ArtDirectionLab.tscn](../scenes/art/ArtDirectionLab.tscn) | 기존 실제 8방향 사냥을 새 초원에 표시. 원래 맵과 비교 버튼, 영웅 원화 보기 버튼 제공. 전투 영웅은 기존 그림과 동작을 사용한다. |

Godot 4.7.2에서 두 장면 중 하나를 열고 **F6**로 실행한다. 초원 시범의 `원래 맵과 비교` 버튼은 같은 전투의 표시 맵만 전환한다. `영웅 원화 보기`로 새 캐릭터 원화를 보고, `초원 사냥 시범 보기`로 돌아오면 저장하지 않는 새 시범 세션이 시작된다. 일반 F6 실행에는 별도의 환경 변수 설정이 필요하지 않다.

## 확정된 방향과 이번 단계의 범위

- 가로형 게임 방향과 기존 1280×720 논리 화면을 유지한다.
- 여러 방향, 현재 8방향 접근을 포함한 몬스터 등장과 자동사냥을 유지한다.
- 진형, 아군별 이동·타깃 선택, 공격 범위, 피해·회복·보호막, 스킬·궁극기 시간은 변경하지 않는다.
- 경험치, 장비 200칸, 보상·재화·강화·저장 규칙과 기존 레이드 강화값은 비주얼 변경 대상이 아니다.
- 레온하르트의 검·방패와 탱커 정체성을 유지한다. 사용자의 ‘검사’ 선택을 공격형 직업으로 전환하라는 요청으로 해석하지 않는다.
- 시안의 원화 방향, 부위별 제작 명세, 독립 시범 화면을 먼저 검수한다. 원화 한 장으로 새 16종 동작이 완성됐다고 표현하지 않는다.

참고 영상의 분위기는 색·비율·명암·공간감·동작 리듬으로 나눠 평가한다. 동일한 게임의 완성도나 ‘90% 일치’를 수치로 보장하지 않는다. 실제 게임 화면과 모션을 함께 보고 가까워졌는지 판단한다.

## 기존 자산과 리깅 조사

## 신규 원화와 부위 분리 명세

[hero-part-spec.json](../assets/art-direction/pilot-01/hero-part-spec.json)은 **런타임에 연결되지 않은 제작 제안서**다. 21개 관절과 31개 표시 파트의 부모, 공통 캔버스 기준 피벗, 앞뒤 순서, 접합부 겹침 길이를 기록했다. 수치는 신규 원화 검수 후 조정해야 하며 실제 그림에서 측정한 값이 아니다.

현재 생성한 원화 시안은 1164×1351px이다. 후속 파트 제작용 공통 캔버스는 2048×2048, 캐릭터 몸 높이 1200~1680px를 제안하며, 기존 시안 파일이 이 제작 규격을 이미 충족한다고 간주하지 않는다. 얼굴·검·방패는 강체로 유지하고 머리카락 끝·망토·천에만 제한적인 변형을 적용한다. 원화가 한 장 생성되거나 시범 화면에 놓였다는 사실은 분리 파트가 만들어졌다는 의미가 아니다. **이 명세를 작성한 단계에서 새 원화의 부위 분리와 새 16종 동작은 아직 완료되지 않았다.**

분리 시에는 방패 뒤 팔·몸통, 팔 아래 옷, 머리카락 뒤 얼굴, 팔꿈치·무릎 안쪽을 추가로 그려야 한다. 보이는 영역만 잘라 붙이면 큰 동작에서 빈틈이 생긴다. 각 파트를 가운데 재정렬하지 않고 공통 캔버스 좌표를 보존하며, 잘라서 저장할 때는 잘린 원점과 관절 피벗을 함께 기록한다. 기본 16px 여백과 관절별 24~48px 겹침은 시작 제안으로, 실제 동작에서 틈이 있으면 늘린다.

기존 `HeroSkeletalBillboard`는 하나의 바인드 그림·단일 스킨 메시를 전제로 한다. 파트 PNG를 준비하는 것만으로 자동 호환되지 않는다. 시범용 파트 리그와 표시 전용 어댑터를 구현하고, 기존 `play_state`·`play_visual`·`visual_sequence`·`speed_scale`·행동 종료 계약을 유지해야 한다. 전투가 결정한 시점에 그림을 맞추며 그림이 피해·재화·실제 이동을 결정하지 않게 한다.

## 독립 시범과 저장 격리

새 초원은 실제 사냥 흐름 위에 표시하지만 독립 시범 장면에서만 사용한다. 발밑 그림자, 캐릭터 크기, 전경 가림, 밝기·채도, 지면과 발의 접촉을 검토하는 단계다. 사냥 화면에서는 기존 영웅과 동작을 유지하고, 정적인 새 원화와 기존 골격 동작을 합쳐 신규 애니메이션 완성으로 소개하지 않는다.

[ArtDirectionLab](../scripts/art/ArtDirectionLab.gd)은 `PortraitMain`을 상속해 사냥·진형·피해·보상 코드를 재사용한다. 진행·설정 로드를 차단하고 자동 저장·명시 저장·화면 전환·종료 콜백에서도 진행·설정 파일을 영속 저장하지 않도록 처리한다. 시범 안에서 얻은 보상이나 바꾼 설정은 그 세션의 메모리에만 남는다.

기존 기본 저장 경로는 `user://pixel_war_save.json`이다. 시범은 초기화 단계부터 `save_state_path`를 `user://art-direction-lab/progress.json`, 설정 경로를 `user://art-direction-lab/preferences.cfg`로 분리하고 로드·저장 구현 자체도 차단한다. 이 두 시범 파일도 생성하지 않는다. 레이드 메뉴를 열고 전투를 마친 경우에만 별도 보고서 `user://art-direction-lab/raid-reports.json`를 기록하며 필요한 디렉터리를 시범이 만든다. 기본 레이드 보고서 경로는 사용하지 않는다.

[HeroConceptStudy](../scripts/art/HeroConceptStudy.gd)는 비교 화면만 표시하고 `Main`, 저장 서비스, 전투 리그를 생성하지 않는다. F6로 보는 사용자는 `XDG_DATA_HOME`을 별도로 지정할 필요가 없다.

반면 [자동 테스트](../scripts/ArtDirectionPilotSmokeTest.gd)는 저장 보호를 검증하기 위해 기본 경로 형태의 임시 검증용 파일과 백업을 만든다. 따라서 **경로에 `art-pilot`이 포함된 폐기 가능한 새 `XDG_DATA_HOME`에서만 실행**한다. 이미 저장 파일이 있으면 덮어쓰지 않고 검사를 중단한다. 실행 시작·메뉴 이동·8방향 전투·명시 저장·레이드 보고서·종료 전후에 기본 파일의 해시와 존재 상태를 비교한다.

## 검증 범위와 결과 위치

이번 코드 검사는 **새 스크립트 6개**에 한정한다. 전체 운영 코드 405개를 다시 검사했다고 표기하지 않는다. 선택 회귀는 시범의 실제 8방향 적 생성·접근·HP 감소·자동 클리어·2부대/25명 상한, 동일 전투에서의 맵 비교, 버튼 실제 포인터 입력과 원화 장면 왕복, 기본 저장본 보호를 대상으로 한다.

최종 집계는 [regression.json](../checks/art-direction-pilot/regression.json)에, 실제 화면은 [captures](../checks/art-direction-pilot/captures)에, 실제 실행 영상은 [pilot-live.mp4](../checks/art-direction-pilot/pilot-live.mp4)에 남긴다. Godot 4.7.2에서 새 스크립트 6/6개와 시범 통합 검사 272/272항목을 통과했다. 실제 캡처 7장과 24 FPS 고정 Movie Maker 실행 영상을 남겼다. 24 FPS는 녹화 설정이며 기기 성능 측정값이 아니다. 자동 테스트 통과는 Android 실기기 성능이나 신규 영웅 동작 완성을 뜻하지 않는다.

이전 레이드 단계의 스크립트 405개·회귀 22종·숫자로 집계한 17,405항목·화면 13장은 [레이드 검증 기록](RAID_STRENGTH_QUALITY_KO.md)과 `DEVELOPMENT_STATUS.json.previous_raid_quality_validation`에 보존한다. 이 숫자를 이번 신규 아트 시범의 통과 수로 재사용하지 않는다.

| 4. 16종 동작 | 기존 16개 상태와 새 파트 원화 연결 | 반복 행동 재시작·회피·방어·버프·궁극기·승리·등장 및 상태 전환 검수. 기존 전투 타이밍 유지 |
| 5. 대표 4인 파티 | 근접 수호자·원거리·마법·지원 역할의 대표 영웅 | 동시에 움직일 때의 구분, 가림, 이펙트 가독성, 실제 모바일 프레임 측정 |
| 6. 전체 30명과 맵 확대 | 확정된 제작 기준을 다른 영웅·맵에 적용 | 영웅별 무기·실루엣·행동 차이, 진행도·세이브 호환과 전체 사냥 회귀 검증 |

핵심 6동작은 첫 제작 묶음이며 기존 게임에서 다른 10종을 삭제하라는 의미가 아니다. 16종 전체는 `idle`, `walk`, `run`, `attack_1`, `attack_2`, `skill`, `ultimate`, `hit`, `knockback`, `dodge`, `guard`, `buff`, `debuff`, `victory`, `death`, `spawn`을 뜻한다. 현재 모든 영웅에 해당 이름이 존재해도 새 원화에 맞춘 동작 완료 수로 합산하지 않는다.

대표 파티와 전체 확장 전에 추가 방향 원화의 범위, 목표 Android 기기, 동시 등장 수를 실제 화면과 성능을 보고 정한다. 세계의 8방향 사냥을 유지하는 것과 캐릭터 원화 8방향을 이미 보유한 것은 서로 다른 조건이다.

## 함께 검수할 내용

사용자는 시안에서 가장 마음에 드는 얼굴·비율·색감과 어색한 동작을 골라 주면 된다. 구현 쪽에서는 비교 가능한 동일 장면 캡처·짧은 동작 영상·실제 표시 크기를 제공하고, 사용자 피드백을 관절·원화·타이밍 수정으로 연결한다. 최종 품질은 고해상도 원화 한 장이 아니라 실제 사냥 화면에서의 일관성과 움직임으로 판단한다.
