# 종의전쟁 코드 구조 원칙

월드전쟁 기능 때문에 기존 개인 RPG 코드가 꼬이지 않도록 다음 경계를 유지합니다.

## 1. 개인 RPG 레이어

기존 `Main.gd`의 영웅 성장, 장비, 자동사냥, 레이드, 소환은 개인 RPG 기능으로 유지합니다.
전쟁 타일 판정, 행군 시간, PvP 결과 계산을 이 코드에 직접 넣지 않습니다.
개인 RPG와 전쟁의 연결은 현재 자동사냥의 군량 획득처럼 명확한 자원 인터페이스만 사용합니다.

## 2. 전쟁 영토 레이어

`WorldWarState.gd`는 `RefCounted` 순수 상태 객체입니다.
20×20 월드, 타일 소유권, 수도 안전지대, 열세 진영 보호, 보급선 경로, 군량, 점령 규칙과 저장/복원을 담당합니다.
UI나 영웅 전투 이펙트를 알지 못합니다.

## 3. 행군 레이어

`WorldMarchState.gd`는 영토 상태와 분리합니다.
행군 경로, 이동 시간, 군량 비용, 진행률, 취소/환급, 오프라인 경과와 저장/복원만 담당합니다.
타일 자체를 그리거나 영웅 스탯을 계산하지 않습니다.

## 4. 전투 해결 레이어

`WorldBattleResolver.gd`는 네트워크/UI와 분리된 결정론적 10vs10 계산기입니다.
공격/수비 스냅샷, 공격대 피로, 수비 진영 보정과 시드만 입력받아 전투 결과를 반환합니다.
실제 서버가 붙으면 동일 입력을 서버에서 계산하거나 검증할 수 있게 유지합니다.

## 5. 렌더링 레이어

`WorldWarMapView.gd`는 타일, 안전지대, 최후 방어선, 행군 경로, 내 부대 위치를 그립니다.
어떤 타일을 공격 가능한지 스스로 결정하지 않습니다.

## 6. 화면 레이어

`WorldWarScreen.gd`는 선택 타일 정보, 열세 버프, 출정, 행군 취소, 수도 귀환을 보여줍니다.
실제 규칙 판정은 `WorldWarState`와 `WorldMarchState`에 위임합니다.

## 7. Main 연결부

`Main.gd`는 다음 역할만 가집니다.

- 전쟁 화면으로 이동
- 현재 진영/원정대 전투력 전달
- 영토 및 행군 상태 저장/불러오기
- 개인 자동사냥에서 군량 공급
- 전쟁 상태 변경 시 기존 저장 함수 호출

## 8. 수비대/리포트 상태

타일 수비 스냅샷, 부대 피로와 최근 전투 리포트는 `WorldWarState.gd`에 저장합니다.
전투 계산 자체는 저장 객체가 수행하지 않습니다.

## 다음 모듈

v14의 유저 부대 vs 유저 부대 전투는 `WorldBattleResolver.gd`로 분리합니다.
수비대 목록/전투 큐/전투 리포트 역시 `Main.gd`가 아닌 전쟁 도메인 아래에 둡니다.
이 경계를 유지하면 향후 서버형 SLG로 바꿀 때 개인 자동사냥 코드를 재작성하지 않아도 됩니다.


## v15 확장 경계

`WorldSupplyNetwork.gd`는 보급 연결을 계산하는 순수 서비스입니다. 타일 소유권을 직접 바꾸지 않습니다.

`WorldConflictState.gd`는 한 타일에 여러 부대가 존재하는 전선 상태를 담당합니다.
주둔 한도, 공격 FIFO, 집결 참여, 개인 공헌도는 여기에서 관리하고 실제 10vs10 수치 계산은 계속 `WorldBattleResolver.gd`에 위임합니다.

중요한 원칙:
- `Main.gd`에 SLG 전투 규칙을 추가하지 않음
- 렌더러에서 점령/보급 규칙을 판정하지 않음
- 전투 계산기에서 타일 소유권을 직접 관리하지 않음
- 실제 멀티플레이 전환 시 `WorldConflictState`의 저장/명령 부분을 서버 API로 대체

## v18 시즌/프로토콜 레이어

`WorldSeasonState.gd`는 시즌 기간, 진영 점수, 개인 공헌도와 시즌 리셋 범위를 담당합니다.
영웅/장비 같은 계정 영속 데이터는 알지 못하며, 전쟁 월드 상태만 리셋합니다.

`WorldAuthorityService.gd`는 시즌 점수 변경과 정산 단계의 전쟁 명령 잠금을 담당합니다.
클라이언트 UI가 시즌 점수를 직접 변경하지 않습니다.

권한 서버 스냅샷은 world/march/conflict/season을 하나의 protocol payload로 취급하며 digest를 검증합니다.
실제 원격 서버로 전환해도 ClientSession의 적용 경계는 유지합니다.
