# Pixel RPG v28 · 넓은 필드와 밝기 조정

이번 작업은 v27 저장본을 바탕으로 사용자가 승인한 밝고 귀여운 아트를 적용하고, 작은 영웅들이 넓은 맵을 이동하며 사냥하도록 연결한 개발 체크포인트다. 배경을 어둡게 바꾸지 않고 밝기를 90%, 채도를 88%로 조정했다. 테스트 통과 수를 게임 전체 완성률로 환산하지 않는다.

## 적용 내용

| 항목 | 현재 동작 |
|---|---|
| 필드 | 32×20 월드, 화면 밖까지 이어지는 지도, 부드러운 카메라 추적과 가장자리 제한 |
| 캐릭터 크기 | 1280×720 기준 영웅 약 40px, 일반 몬스터 36~44px |
| 자동사냥 | 영웅별 위치·목표·사거리, 근접 접근, 원거리 거리 유지, 사망·회복, 장애물 우회 |
| 몬스터 | 실제 영웅을 추격·공격하고 서식지로 귀환. 지원 몬스터는 가까운 아군을 회복 |
| 후퇴 동작 | 서식지 밖까지 계속 도망쳐 몬스터가 귀환·전회복하는 반복을 막도록 후퇴 목표 제한 |
| 영웅 아트 | 레온하르트·미라·오르윈·다리우스·카엘룸, 4방향 대기·걷기·공격 |
| 몬스터 아트 | 고블린·들개·멧돼지·두더지·버섯·늑대 6종 |
| 이미지 적용 | 실제 알파 경계로 104개 프레임 분리. 원본 PNG 픽셀을 바꾸지 않고 잘림과 발 위치 흔들림 방지 |
| HUD | 상단 단계·재화, 넓은 필드, 10칸 편성·체력·궁극기, 하단 5개 메뉴, 접이식 사냥터 정보 |
| 글자·색 | 나눔고딕과 라이선스 포함. 크림·민트 배경과 진한 본문, 큰 재화 만/억/조 표기·정확한 값 툴팁 |
| 전투 가독성 | 고정 대형 스킬 배너 제거, 실제 대상에 작은 효과, 피해 숫자 동시 10개 제한, 짧은 궁극기 알림 |

초상화의 궁극기 바는 실제 영웅 전투 상태의 충전량을 사용한다. 단계 진행 표시는 몬스터 개체 수와 혼동되지 않도록 ‘무리 격파’로 표기한다. 보스·성장·장비·영토전·저장 기능은 v27 구조를 유지하며 회귀 검증 대상에 포함한다.

## 확인 중 발견하고 고친 문제

- 필드 화면이 바뀌며 낡은 테스트가 숨겨진 메뉴나 이전 노드 부모를 찾던 문제: 실제 표시·스크롤 접근·좌표 일치를 확인하도록 수정했다.
- 개별 위치를 사용하면서 지원 몬스터의 회복이 영웅 공격 사거리에 묶였던 문제: 아군 회복 범위와 영웅 공격 범위를 분리했다.
- 숲의 원거리 후퇴가 서식지 귀환을 반복 유발하던 문제: 공격력·피해량을 바꾸지 않고 후퇴 목표를 서식지 안으로 제한했다.
- 실제 촬영에서 발견한 상단 동쪽 나무의 충돌 영역 누락: 원본 지도에 맞춰 해당 영역만 추가했다.
- 작은 캐릭터를 가리던 큰 고정 이펙트, 중첩 알림과 대상 텍스트를 줄였다.

## 실행 검증

최신 고유 결과는 **71개 스크립트 모두 통과**다. 최초 전체 실행은 70개 중 65개가 통과했고, 그 실패 기록을 보존했다. 문제를 수정한 뒤 관련 14개(신규 후퇴 회귀 검사 1개 포함)를 재검증했다. 나무 충돌 보정 후 이동·길찾기·장기 사냥·밸런스 4개를 다시 실행했고, 이동 검사의 사거리 전제에 살아 있는 영웅 상태를 명시한 후 해당 검사까지 통과했다. 테스트 통과를 위해 능력치나 통과 기준을 완화하지 않았다.

- `docs/v28-runtime-results.json`: 최신 고유 71/71 결과와 각 실행 근거.
- `docs/v28-runtime-initial-results.json`: 최초 전체 실행의 실패 포함 원본.
- `docs/v28-targeted-retest.json`, `v28-navigation-final-retest.json`, `v28-reach-fixture-final.json`: 수정 후 재검증 기록. 중간 실패도 그대로 보존.
- Godot 4.7.2 실제 렌더링으로 **1280×720, 30fps, 20초** 플레이 영상 촬영. 영웅 5명이 약 19.4~22.2 월드 단위를 이동했고 2개 무리를 격파했다. 영상은 정상 물리 업데이트를 녹화했으며 합성 시안이 아니다.
- 실제 지도·스프라이트·HUD 화면 확인, 정적 리소스 검증, Godot 4.7 호환성 검사 완료.

| 10인 지속 사냥 | 아우렐리아 | 녹스페라 |
|---|---:|---:|
| 게임 내 180초 무리 격파 | 25 | 26 |
| 실제 행동한 영웅 | 10명 | 10명 |
| 가장 긴 격파 간격 | 11.3초 | 11.7초 |
| 강제 전멸 후 회복 | 4.4초 | 4.4초 |

밸런스 측정은 15조건×60초, 145개 판정을 통과했다. 숲 3인은 6무리/7무리, 숲 10인은 6무리/7무리였다. 숲 10인의 방치 일반 골드 추정은 실제 일반 골드 대비 각각 1.560배/1.337배였다. 단계 상자와 장비 등을 제외한 표본이므로 총수익으로 해석하면 안 되며, 방치 경제 재조정은 남아 있다. `docs/v28-balance-results.json`에 원시 수치를 보존했다.

재현: `python3 tools/run_tests.py --godot /path/to/Godot --jobs 3 --output results.json`. 각 검사는 독립 저장 경로에서 실행한다. 기존 `SkillSmokeTest`의 종료 시 ObjectDB 경고는 남아 있으며, 스크립트 오류나 실패 종료는 없었다.

## 남은 작업과 범위

- 나머지 영웅·몬스터·보스의 아트 통일과 성장·전쟁 등 세부 화면의 디자인 마감이 남아 있다. 첫 사냥터의 까마귀 등 일부 이미지는 기존 아트다.
- 현재 16포즈 영웅 아틀라스는 방향별 대기·보행·공격을 담는다. 피격·사망은 프레임 표시와 색·투명도 연출을 결합한다. 레온하르트 10개 고유 동작 각각의 독립 애니메이션 완성을 뜻하지 않는다.
- 넓은 맵에서 이동 시간이 달라졌으므로 방치 추정과 실제 사냥 수익은 장기 플레이로 재조정해야 한다. 1분 밸런스 표본만으로 출시 경제 균형을 확정하지 않는다.
- Android 실기기 성능·터치·발열·장시간 저장과 운영 서버·실시간 협동 레이드는 이번 Linux 실행 검증 범위 밖이다.
- 이번 결과는 요청한 화면·맵·이동 사냥 변경의 구현 기록이며, 모든 영역의 출시 완성도가 95% 이상이라는 표시는 하지 않는다.

## 적용 방법

`pixel-faction-rpg-v28-bright-moving-checkpoint.patch`는 원래 v25 프로젝트 ZIP에 v26~v28 변경과 새 아트를 한꺼번에 적용하는 누적 패치다. v27에 덧대는 패치가 아니다.

1. `pixel-faction-rpg-prototype-v25-godot47-combat-fx-runtime-verified.zip`을 새 폴더에 푼다.
2. 추출된 프로젝트 폴더에서 다음 명령을 실행한다.

```sh
git apply --check /path/to/pixel-faction-rpg-v28-bright-moving-checkpoint.patch
git apply /path/to/pixel-faction-rpg-v28-bright-moving-checkpoint.patch
```

3. Godot 4.7.2로 `project.godot`을 열고 리소스 가져오기가 끝나면 실행한다.

패치는 원본 v25의 새 추출본에 실제 적용하고 파일 목록·내용 해시·크기·파일 모드가 작업본과 일치하는지 확인한 후 생성한다. 기존 작업 폴더에 중복 적용하지 않는다.
