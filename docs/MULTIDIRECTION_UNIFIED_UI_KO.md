# 다방향 자동사냥과 UI 통합 — Godot 4.7.2

작업 브랜치: `work/multidirection-unified-ui`. 레이드 맵과 30명 영웅 골격 작업을 포함한다. 현재 소스·검토 캡처를 보관하며 main에는 병합하지 않았다.

## 자동사냥

오른쪽에 고정돼 있던 등장 좌표를 동 → 서 → 북 → 남 → 북동 → 남서 → 북서 → 남동 순서의 8개 입구로 바꿨다. 연속 부대가 같은 방향에 몰리지 않으며 8부대마다 반복한다. 각 입구에서 5열 부대가 전장 중심을 향하도록 배치하고, 다음 줄은 안쪽으로 확장한다. 입구를 벌려 모서리에 몬스터가 겹쳐 쌓이는 경우를 줄였다.

`InvasionHuntDirector.entry_side()`가 위치·방향 이름을 한 곳에서 정의한다. 실제 적에는 `entry_side`를 기록하며 HUD는 현재 진입 방향을 표시한다. 위치는 이동 가능 영역에 맞춘다. 영웅은 선택한 진형을 유지하고 기존 위협 선택·공격·회복 규칙을 사용한다.

화면 확인에서 최초 영웅 배치가 진형 목표와 달리 좁은 임시 좌표를 사용하는 문제를 발견했다. 전장 생성 직후부터 선택한 진형의 위치를 사용하도록 수정했다. 전투 중 진형 변경은 순간이동 없이 기존 이동 처리를 사용한다.

15–20마리, 생존 적 5마리 이하에서 증원, 최소 4게임초 간격, 최대 생존 25마리·2부대 제한과 부대별 한 번만 받는 보상은 유지한다. 던전·탑·심연·레이드의 자체 등장 규칙은 수정하지 않는다. 두 진영의 자연 전투에서 8개 입구를 지나 계속 다음 부대로 진행하는지 검사한다.

## 공통 UI

`GameUiTheme`을 팔레트의 기준으로 삼고 `PortraitSkin`도 같은 색을 읽도록 했다. 어두운 바탕, 두 단계의 패널, 밝은 본문, 차분한 보조 글자, 금색 주요 행동을 사용한다. 버튼 상태·둥근 모서리·얇은 테두리·폰트·스크롤과 내비게이션도 공통 기준을 사용한다. 체력·위험·진영·등급 색은 의미를 유지한다.

| 화면 | 변경 |
|---|---|
| 자동사냥 | 상단 정보 압축, 넓은 전장, 한 줄의 좌우 스와이프 편성, 설정·사냥 시작/정지·속도의 단일 명령 줄 |
| 사냥 설정 | 스킬·각성기 자동 사용, 진형, 피해/보상 정보, 지도, 목표, 오프라인 보상, 화면/소리 설정을 한 곳에 모음 |
| 레이드 | 세로 전장 확대, 한 줄의 좌우 스와이프 편성, 공략·자동 사용·보고서를 설정 창으로 이동, 시작/수동 기술과 회피는 전장 가까이 유지 |
| 캠프 | 사냥 행동을 먼저 표시하고 편성·목표·보상을 아래로 정리 |
| 영웅·성장·가방·소환 | 공통 카드·버튼·지표 표현, 중첩된 지표 카드 제거, 중복 능력치 문장 숨김, 보조 전투 성향은 펼쳐 보기 |
| 지도·콘텐츠·도감·보상·장비 상세·연구·보고서·종의전쟁 | 공유 페이지 구성과 테마 적용, 기존 기능의 콜백 유지 |
| 메뉴 | 전투와 탐험 / 영웅과 성장 / 보상과 계정으로 묶고 빠른 설정은 펼쳐 보기 |
| 하단 내비게이션 | 홈·영웅·전투·가방·메뉴의 동일한 크기와 선 아이콘, 선택된 항목만 강조 |

설정에서 다른 대화창을 열 때 현재 설정 창을 먼저 숨겨 새 창의 입력이 가려지지 않도록 했다. 뒤로 가기는 사냥·레이드 설정 창부터 닫는다. 작은 편성 해제 버튼의 좌우 여백과 상단 이름·레벨의 실제 폰트 높이도 보정했다.

## 실제 검토 화면

`checks/unified-ui/captures/`는 Godot Forward+에서 찍은 실제 게임 화면이다. `tools/capture_unified_ui.gd`로 다시 만들 수 있다. 매 실행마다 새 테스트 저장을 사용해 오프라인 보상 창이 캡처를 덮지 않게 했다.

- `lobby`, `heroes`, `hero-detail`, `growth`, `inventory`, `content`, `summon`, `world`, `rewards`, `war`, `menu`
- `hunt`, `hunt-settings`, `raid`, `hunt-landscape`, `raid-landscape`
- `entry-<direction>`: 실제 부대 생성기를 사용한 입구 검토 장면. 이전 부대의 체력을 테스트에서 소진해 각 입구를 빠르게 확인한 정지 장면이며 자연 진행 영상은 아니다.
- `raid-warning`, `raid-mobile-scale`: 실제 경고 표시와 450×800 창 배율 검토. 지정한 보스 패턴을 테스트에서 표시한 장면이다.

## 재현과 검증

Godot 4.7.2에서 다음 도구를 실행한다.

```sh
godot --path . --script tools/capture_unified_ui.gd
godot --headless --path . --script tests/regression/MultiDirectionHuntSmokeTest.gd
godot --headless --path . --script tests/regression/UnifiedInterfaceSmokeTest.gd
godot --headless --path . --script tests/regression/V49PortraitLayoutSmokeTest.gd
godot --headless --path . --script tests/regression/V52HuntUiSmokeTest.gd
```

시험마다 별도 저장 디렉터리를 사용한다. 실행 결과는 `checks/unified-ui/regression.json`에 보관한다. 다방향 이동·증원·보상, 진형, 화면 회전, 공통 메뉴, 성장·종의전쟁, 전투 카메라·경고 투영, 레이드 맵과 UI 배치를 확인한다.

최종 결과: GDScript 385개 구문 검사와 실행 검사 13종 통과. 화면 배치는 159개 상태의 21,928개 검사, 사냥 HUD는 2,694개 검사에 통과했다. 구조 검사 12종도 통과했다. 실제 렌더 캡처는 26장이다. 설정 창이 열린 상태의 크기 변경도 별도 검사해 HUD가 정상 재구성되는지 확인했다.

소프트웨어 Vulkan 렌더러에서 확인했다. 모바일 크기와 창 배율 검증은 Android 실기기의 터치·FPS·발열 검증을 대신하지 않는다. 기존 저장 및 온라인 시스템은 바꾸지 않았다.
