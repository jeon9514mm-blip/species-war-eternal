# 개별 사냥과 메뉴 중 사냥 유지

홈의 실제 사냥을 영웅·가방·성장·콘텐츠·사냥터 선택 화면에서도 계속 진행합니다. 메뉴에서 홈으로 돌아오면 같은 전장의 적과 영웅 HP, 쿨다운, 무리 진행을 이어갑니다. 수동 일시정지와 앱이 백그라운드로 내려간 상태에서는 진행하지 않습니다. 화면은 두 개여도 전투 상태와 지갑은 Main 하나만 사용합니다. 편성이 바뀌면 남아 있는 영웅과 해제 후 다시 출전하는 영웅의 HP 비율·사망 상태·쿨다운을 유지하고 출전 배우를 갱신합니다. 관련 메뉴 수치와 복귀 보상 안내는 [사냥 중 상태 수정](HUNT_MENU_STATE_FIX_KO.md)을 따릅니다. 실제 던전·연습·레이드 입장, 진영·지역 전환은 각 콘텐츠의 전환 경로를 따릅니다.

일반 사냥의 영웅은 좁은 대형 고정 제한을 벗어나 자신의 목표를 추적합니다. 역할별 이동 범위는 지원 4, 기본 5, 측면 공격 6 월드 단위입니다. 출발 대형과 대형 능력치는 기존 선택을 사용합니다. 목표에 이미 몰린 영웅 수와 가까운 공격 가능 적을 함께 고려하며, 같은 적 집중 공격 패시브와 마무리 공격 우선순위는 유지합니다. 일반 공격도 해당 영웅의 이동 목표를 실제 사거리 안에서 사용합니다. 공격 범위와 장애물 통과 규칙은 기존 판정을 따릅니다.

몬스터는 영웅까지의 거리, 역할과 현재 몰린 수를 보고 개별 목표를 선택합니다. 도발은 우선하고 죽은 영웅은 제외합니다. 같은 영웅에게 접근하는 적은 진입 방향과 순서를 이용해 서로 다른 접근 위치를 고릅니다. 짧은 목표 유지 시간을 두어 매 프레임 목표가 바뀌는 현상을 줄였습니다. 막힌 추적이 2.5초 동안 진전되지 않으면 그 목표의 비용을 4초간 높여 다른 적을 다시 찾습니다. 이는 현재 전투의 이동 결과에 반응하는 규칙 기반 AI이며, 신경망 모델 훈련이나 영구 학습 데이터 저장은 포함하지 않습니다.

사냥 보상과 정기 저장은 주 화면에서 복사한 스냅샷을 단일 작업 스레드에 넘깁니다. 요청이 겹치면 모아서 저장하며, 구매·보상 수령·편성·앱 중단·종료 등 기존 즉시 저장은 이전 작업이 끝난 후 최신 상태를 저장합니다. 이전 스냅샷이 구매 결과를 덮어쓰는 경쟁을 막습니다. 작업 저장 실패도 기존 저장 보호 상태로 연결하고, 재시도는 현재 상태만 저장해 보상을 중복 지급하지 않습니다. 저장 실패 보호가 나타나기까지 진행된 최신 상태는 메모리에 남습니다.

Android 뒤로 가기 알림은 현재 팝업의 Escape 처리와 연결했습니다. 팝업을 먼저 닫고 일반 메뉴에서는 홈으로 돌아갑니다. 실제 터치 저장 재시도는 닫힌 입력 대상을 숨기고 프레임 종료에 삭제해 엔진의 마우스 변환 종료와 터치 종료를 모두 처리합니다.

검사에서는 10인 영웅·원형 12적·20초 고정 조건의 평균 영웅 간 거리가 아우렐리아 1.91→3.94, 녹스페라 2.03→4.43 월드 단위로 증가했습니다. 두 진영의 실제 전투가 여러 무리를 처치했고 몬스터가 최대 네 영웅을 동시에 나눠 추적했습니다. 시작 영웅 세 명도 8개 진입 방향 모두에서 자연 전투로 첫 부대를 처치했습니다. 3,200개 장비의 저장 측정에서는 주 화면 작업 시간이 약 453ms에서 9ms로 줄었습니다. 수치는 headless VM의 해당 조건에서 측정한 값입니다.

메뉴·터치·지갑·저장 보호·실제 사냥·역할·편성·연습 전투 검증은 [검사 기록](../checks/independent-hunt/validation.json)에 있습니다. 당시 넓게 실행한 기존 레이드 품질 검사에서 영웅 선택 영역 크기와 회피 버튼 근처 바닥 겹침 두 실패가 변경 전에도 재현됐습니다. 이후 [레이드 터치 선택과 전장 겹침 수정](RAID_TOUCH_LAYOUT_KO.md)에서 두 문제를 해결하고 해당 검사 전체를 통과했습니다. Godot 4.6.3에서 검사했으며 프로젝트 기준 4.7.2와 Android 실기기·APK 검증은 별도로 필요합니다.
