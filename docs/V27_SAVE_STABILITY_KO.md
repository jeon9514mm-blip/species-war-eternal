# V27 저장·복구 안정성 검증

2026-09-22, Godot 4.7.2 Linux headless 기준. 이 문서는 저장 영역에서 구현하고 실행한 내용을 기록한다. 출시 완성도나 실기기 검증을 백분율로 추정하지 않는다.

## 이번에 닫은 결함

기존 저장은 임시 파일 작성 후 교체만 수행했다. 잘린 JSON의 대체본, 저장 무결성 확인, 미래 버전 보호가 없었고, 중첩된 성장 데이터의 잘못된 타입이나 음수·과대 수치가 게임 계산까지 전달될 수 있었다. 반복된 앱 일시중단 알림은 오프라인 기준 시각을 덮어쓸 수 있었으며, 최신 저장에서 의도적으로 비운 파티도 구버전 마이그레이션 분기로 3명이 복원되었다.

| 마감 기준 | 구현과 확인 |
| --- | --- |
| 파일 작성 도중 실패해도 기존 저장 유지 | 검증된 `.tmp` 완성 후 교체. 임시 파일 및 백업 쓰기 실패를 실제 파일 경로로 재현해 기존 골드 보존 확인 |
| 정상 백업에서 자동 복구 | primary → `.bak` → 검증된 `.tmp` 순서. 정상 primary는 임시 파일보다 우선 |
| 손상 원본이 정상 백업을 덮지 않음 | 무결성 검사를 통과한 primary만 백업으로 회전. 손상 원본은 `.corrupt` 1개로 보관하며 보관 실패 시 교체 중단 |
| 형식상 정상 JSON의 손상 감지 | 기존 flat JSON에 `_save_integrity` 메타 추가. 정규화한 JSON의 SHA-256 확인. v27 메타 누락도 거부 |
| 버전 이행과 다운그레이드 보호 | v1~26 plain JSON 허용, 저장 시 v27로 이행. 미래 버전 primary 또는 복구용 backup을 덮어쓰지 않음. 타이틀에 업데이트 안내 및 시작 차단 |
| 잘못된 저장 필드로 런타임 오류 방지 | 숫자·문자열·boolean·배열·딕셔너리 타입 검증. 비정상 수치, 알 수 없는 영웅·퀘스트·지역 ID, 중복 편성 및 중복 장비 ID 정리 |
| 성장 데이터의 규칙 유지 | 영웅/반려동물 레벨 100, 장비 강화 10, 레벨에 따른 스킬 포인트 예산, 장비 슬롯 3개·등급 3개·세트 4개 검증 |
| 구버전 진행 보존 | v4 기본 영웅 3명과 기존 편성 한도를 이행. 최신 버전의 빈 파티는 그대로 유지. 최신 편성에는 진영·해금·인원 제한 적용 |
| 일시중단과 중복 보상 방어 | 중복 pause의 기준 시각 덮어쓰기 차단. resume 반복/보상 함수 반복/즉시 reload 시 보상이 중복되지 않음 |
| 시계 역행 시 저장 시각 유지 | 저장 시 `max(기존 시각, 현재 시각)` 사용. 파일 저장 성공 후에만 해당 저장 시각 확정 |
| 테스트의 사용자 진행 오염 방지 | 각 실행의 `XDG_DATA_HOME`·`APPDATA` 임시 디렉터리 격리. 새 파일 I/O 테스트는 `_ready` 전 별도 저장 경로 지정, 테스트 종료 시 자체 파일 제거 |

## 데이터 규칙

- 골드·XP·젬·보관 보상은 0~1조, 사냥 단계는 V27 성장 규칙에 맞춰 1~10,000으로 제한한다. 이는 손상 입력에 대한 상한이며 경제 밸런스의 적정 수치를 뜻하지 않는다.
- 영웅과 반려동물의 잔여 XP는 해당 레벨의 다음 레벨 필요 XP 미만으로 정규화하고 최대 레벨에서는 0으로 둔다. 초과 XP가 있는 손상 저장을 읽는 행위가 레벨업을 발생시키지 않는다.
- 반려동물 진화는 레벨에서 다시 계산한다. 스킬 트리는 공격→생존→유틸리티 순서로 허용 예산 내 기존 포인트를 남긴다.
- 인벤토리는 최대 30개다. ID 없는 구형 장비는 기존 내용과 위치로 안정적인 ID를 생성하며, 같은 ID의 중복 항목은 제거한다.
- 아직 도달하지 않은 미래 시각은 2100년 상한 안에서 유지해 시계 역행 후 지난 구간을 다시 보상하지 않는다. 기기의 잘못된 시각 자체를 신뢰 가능한 서버 시각으로 바꾸는 기능은 아니다.
- World 관련 최상위 값은 Dictionary만 전달한다. World 내부 스냅샷의 필드 검증은 각 World 클래스의 import 구현과 별도 전쟁 테스트가 담당한다.

## 남은 검증 범위

Android/iOS 실기기의 강제 종료·절전·저장 공간 부족, Windows 파일 교체, 전원 상실에 따른 파일 시스템의 지속성은 이 Linux headless 결과로 증명하지 않는다. Godot의 flush와 같은 디렉터리 rename을 사용하지만 디스크 컨트롤러 장애까지 보장하지 않는다. SHA-256 메타는 우발적 손상 감지용이며 로컬 파일 변조 방지 서명이나 서버 보상 권한을 대신하지 않는다. 백업 복구는 마지막 정상 세대로 돌아가므로 최신 미완료 저장 이후의 진행은 복원 범위 밖일 수 있다.
