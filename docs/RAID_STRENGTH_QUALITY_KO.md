# 레이드 10배 강화와 품질 점검

## 범위와 적용 상태

사용자의 전체 품질 개선 요청을 바탕으로 레이드 난이도·전투 조작·정보 표시와 실제 장비 저장 손실 문제를 우선 점검했습니다. Godot 4.7.2, 가로 1280×720, 장비 가방 200칸, 저장 버전 37과 기존 영웅 화면을 유지합니다.

이전 영웅·전체 메뉴 단계의 기준 커밋은 `5225317abdd65641708c094a397d5ed746cc4a0b`입니다. `work/raid-quality-pass`에서 이번 구현·최종 화면·선택 회귀 검사를 완료했으며 게시 대상은 `main`입니다. 이번 작업은 전역 UI 전체 재설계나 신규 게임 서버 구축을 포함하지 않습니다.

## 보스 기본 수치 10배

`RaidBalance.gd`를 공통 기준으로 사용해 세 보스의 **기본 최대 HP·기본 공격력·권장 전투력**을 기존 값의 10배로 조정합니다. 공격력은 기존 정수화(소수점 버림) 규칙을 적용한 값에 배수를 곱합니다.

| 보스 | 최대 HP | 기본 공격력 | 권장 전투력 |
| --- | ---: | ---: | ---: |
| 초원왕 그룬 | 36,000 | 600 | 5,400 |
| 광맥의 거인 모르굴 | 72,000 | 1,200 | 10,800 |
| 월식의 여왕 셀레네 | 124,000 | 2,060 | 18,600 |

수치는 원본 지역 데이터에서 매번 계산하므로 재도전·불러오기·중복 시작으로 배수가 누적되지 않습니다. 보상, 해금 스테이지, 일반 사냥 능력치는 기존 기준을 사용합니다. 권장 전투력은 안내이며, 전투력이 그보다 낮아도 해금되고 원정대가 편성된 레이드에 도전할 수 있습니다.

10배는 위 세 가지 기본 수치의 배수입니다. 실제 피해량은 방어·보호·보스 패턴과 파티 상태에 따라 달라지며, 클리어 시간이나 체감 난이도가 정확히 10배가 된다는 뜻은 아닙니다.

## 레이드 화면과 조작

`RaidCatalogView.gd`는 보스 카드 3개를 한 줄에 표시합니다. 현재 원정대 인원과 전투력, 보스 HP·공격력, 권장 충족 여부, 해금 조건·토벌 횟수·보상·주요 공략과 레이드 준비 버튼을 같은 화면에서 비교할 수 있습니다.

[레이드 선택 화면](../checks/raid-strength-quality/captures/raid-catalog.png) · [패턴 경고·공략 표시](../checks/raid-strength-quality/captures/forgotten_mine-warning.png)

전투 화면은 준비 상태 보스 HP를 100%로 표시하고, 시작 이후에는 실제 HP를 표시합니다. 남은 시간, 패턴 발동까지 남은 초와 공략, 차단 진행도를 실제 상태에 맞춰 보여 줍니다. 수동 스킬과 각성기 버튼은 선택 영웅의 생존·재사용 시간·게이지·효과 적용 조건을 반영합니다.

회피의 무적 시간은 전원 0.5초이며 재사용 대기는 5초입니다. 기본 공격·수정 파동도 같은 무적 시간을 따릅니다. 재도전 시 캐릭터의 이전 사망 표시를 초기화합니다.

## 장비 보존과 저장 크기 제한

가방 200칸과 레이드 입장·추출 시 확인하는 보호 보관함 3,000개 기준은 그대로 사용합니다. 이미 획득해 저장 대상이 된 유효한 장비는 복원 단계에서 3,000개라는 이유만으로 버리지 않습니다. 중복 ID·잘못된 장비 입력을 검증하는 기존 처리는 유지합니다.

전체 저장 파일의 크기 상한은 **8 MiB**입니다. 이를 초과하면 `SaveStore`가 `too_large` 결과로 저장을 거절하고 이전 정상 저장본을 덮어쓰지 않습니다. 아직 기록되지 않은 상태는 메모리에 남겨 저장 대기와 재시도로 이어집니다. 이 처리는 크기 제한을 넘겨서 저장할 수 있게 만드는 기능은 아닙니다.

저장 대기 중 일부 수동·일괄 장비 소비가 허용되는 문제는 후속 개선 항목입니다. 현재 메모리 상태는 보존되지만, 저장 완료 전 허용하는 조작 규칙을 더 일관되게 정리할 필요가 있습니다.

## 확인한 전투 결과

`RaidStrengthSmokeTest.gd`는 **442개 검사, 실패 0개**를 기록했습니다. 세 보스의 배수, 재시작·불러오기에서 배수 비누적, 공격·기믹·회피, 전투 보고서와 중복 정산 방지를 확인했습니다. [전투 비교 결과 원본](../checks/raid-strength-quality/raid-strength-results.json)을 함께 보관합니다.

자동 전투 비교에서는 아우렐리아 영웅 10명으로 Lv.1과 Lv.60을 각각 실행했습니다. 각 레벨·보스의 이전/신규 비교에서 영웅·장비·펫 상태를 동일하게 복원하고 난수 시드를 고정했습니다. 이전 승리의 보상이나 성장으로 다음 편성이 강해지지 않도록 초기 상태를 다시 적용했습니다. 아래 시간은 실제 벽시계 시간이 아닌 **게임 내 경과 시간**입니다.

| 보스 | Lv.1 기존 | Lv.1 강화 후 | Lv.60 강화 후 |
| --- | --- | --- | --- |
| 초원왕 그룬 | 승리 | 패배 | 승리 · 6.45초 |
| 광맥의 거인 모르굴 | 승리 | 패배 | 승리 · 11.35초 |
| 월식의 여왕 셀레네 | 승리 | 패배 | 승리 · 17.35초 |

Lv.1의 기존 세 보스 전승이 강화 후 모두 패배로 바뀌었고, Lv.60 편성은 강화 후에도 모두 승리했습니다. 이 결과는 정해진 편성에서 강화가 작동한다는 비교 자료입니다. 모든 영웅 조합·장비 성장 구간의 적정 난이도나 장기 밸런스를 검증한 결과는 아닙니다.

## 최종 검증과 제한

Godot 4.7.2에서 **스크립트 405/405개, 현재 선택 회귀 22/22종**을 통과했습니다. 숫자로 집계한 검사는 **17,405개**입니다. 별도 숫자 카운터를 출력하지 않는 `CombatControlsSmokeTest`도 통과했으며, 22종에는 포함하고 17,405개 합계에는 가산하지 않았습니다. [최종 검증 보고서](../checks/raid-strength-quality/regression.json)에 각 검사와 범위를 기록했습니다.

실제 렌더 **13장**을 확인했고 에디터 임포트와 렌더 과정 모두 종료 코드 0으로 완료했습니다. 임포트에서는 기존 UID 보조 파일 3개를 로컬 캐시에서 재생성한 경고가 있었으며, 관련 없는 생성 파일은 변경에 포함하지 않았습니다. [임포트 로그](../checks/raid-strength-quality/editor-import.log)와 [렌더 로그](../checks/raid-strength-quality/render.log)를 보관합니다. 렌더는 Vulkan llvmpipe 소프트웨어 방식으로, Android 성능 측정을 대신하지 않습니다.

추가 실행한 구형 `V59ThreeRaidVisualSmokeTest`는 기준 커밋 `5225317`에도 없는 2D `PortraitRaidStageArt` 노드를 참조해 240초 후 시간 초과했습니다. 이 구형 검사는 통과 22종에서 제외하고 보고서에 별도 시도로 기록했습니다. 현재 3D 레이드 구조는 레이드 선택·전투 품질·V76 화면 검사와 실제 캡처로 확인했습니다. 모든 과거 테스트를 실행·통과했다는 의미는 아닙니다.

이전 영웅·메뉴 단계의 398개 스크립트·15종 회귀·18,975개 검사·15장 캡처는 이전 단계 기록으로 보존합니다.

## 다음 개선 우선순위

1. 저장 대기 중 수동·일괄 장비 소비를 포함한 조작 규칙을 통일합니다. 영웅 버튼의 저장 성공 후 복구는 이번에 수정했습니다.
2. 고레벨·서로 다른 영웅과 장비 조합의 장시간 전투를 비교해 레이드별 목표 클리어 시간과 성장 구간을 조정합니다.
3. 확대 화면과 큰 관절 동작에 맞는 고해상도 캐릭터 원화·분리 신체 아트를 준비합니다.
4. Android 실기기에서 터치, 프레임 속도, 메모리와 발열을 검증합니다.

현재 Android 실기기와 장기 밸런스 검증은 완료하지 않았습니다.
