# Ultra floor, circle and lighting implementation

The real battlefield now binds four 1024 PBR maps: artist stone albedo with packed AO, macro normal, mineral micro normal, and height/cavity/curvature/wetness. The approved mineral painting remains the base. Deterministic Blender authoring measures moss **18.00003%** of floor pixels, with **0 pixels outside the crack band**, and patina on **24.99932%** of actual cracks. Wear, moss and patina each use two authoring stages. Wear is 0.8, AO 0.7, moss emission 0.25, height scale 0.08. Wet regions occupy 13.56% of the floor; they darken stone and reduce roughness from 0.58 toward 0.14, using native sky specular reflection.

`FinalStonePBR` performs actual bounded parallax occlusion traversal and crossing refinement: four steps in balanced mode, eight in quality mode. Micro normals use world triplanar projection; the horizontal floor takes a single projection fast path. The optional **4096×4096** mineral normal is an independently sampled continuous mineral field, not an enlarged 1024 image. `MythicDetailProfile.configure_quality(map_root, true)` binds it. The default 1024 configuration uses about **5.59 MB** of BC7/BC5 mipmapped texture storage; the 4K alternative adds about **20.97 MB**, before other game assets. The quality option is separate from the default balanced Mobile profile.

Walking heroes leave real pooled ground footprints. `UltraFloorFootprints` samples actual presented walking positions every 0.14 seconds and reuses exactly **50 MultiMesh instances in one draw**. Six-second traces fade, freeze on pause and disappear with effects-off/battery mode. No hero position, battle rule, RNG, inventory or damage value is modified.

The hunt and raid inlay now uses three rings, twelve rotating and pulsing rune glyphs, twenty leaves, twenty dust motes, petals, a moving energy pulse, glowing cracks and a bounded UV ripple. It keeps one ground plane and one fixed-cost shader; mote count does not create per-pixel loops. Circle glow is 0.7, inner glow 0.55 and the hunt's real shadow-free moss OmniLight is 0.9. The raid keeps its boss position and phase observers.

The actual directional light is 1.0. Bloom is 0.6, vignette 0.75 and analytic diagonal shafts 0.25. The existing single canvas post pass now also exposes chromatic, film grain, lens distortion and visual-time controls. A static 128-size moon/star sky supplies native image-based reflections without recalculating radiance every frame.

Twenty groups of four ambient dust motes share one canvas and are hidden in battery mode. Native `CameraAttributesPractical` far DOF/bokeh is optional **Forward+ quality only**. Its 0.08 blur and six-unit transition start beyond the complete actual floor depth bounds, preserving all heroes and boss paint in focus. A 0.5-second timer refreshes that bound as the camera moves. Mobile, balanced and battery profiles disable this optional blur. DOF itself is supported on Mobile, but this implementation deliberately gates it to the larger quality budget. See [CameraAttributesPractical](https://docs.godotengine.org/en/stable/classes/class_cameraattributespractical.html).

On an active visible battlefield, the profile changes the native global directional shadow filter using `RenderingServer.directional_soft_shadow_filter_set_quality`: quality uses `SHADOW_QUALITY_SOFT_HIGH` (4), balanced uses medium (3), battery uses very low (1). It is a global setting rather than per-viewport PCF13. See the [documented RenderingServer method](https://docs.godotengine.org/en/stable/classes/class_renderingserver.html#class-renderingserver-method-directional-soft-shadow-filter-set-quality).

Forward+ enables native SSR (16 bounded steps), SSAO, SSIL, SDFGI with occlusion and bounce feedback 0.65, and volumetric fog density 0.006 over 48 units. Mobile uses its supported exponential fog density 0.0018, sky reflection, authored AO and analytic shafts. These Mobile paths approximate the requested visual depth; they are not native SSR/SSIL/SDFGI or volumetric fog. The supported passes are described by [Godot's renderer feature comparison](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html) and [environment documentation](https://docs.godotengine.org/en/stable/tutorials/3d/environment_and_post_processing.html).

Godot 4 has no literal `PCF13` quality option or integer two-bounce SDFGI property. Shadow filtering uses its `ShadowQuality` settings; the requested bounce intent maps to native `sdfgi_bounce_feedback`, not a claimed exact bounce count. See [RenderingServer ShadowQuality](https://docs.godotengine.org/en/stable/classes/class_renderingserver.html#enum-renderingserver-shadowquality) and [Environment SDFGI properties](https://docs.godotengine.org/en/stable/classes/class_environment.html#class-environment-property-sdfgi-bounce-feedback).

Validation completed: `FinalEnvironmentSmokeTest` exercises actual hunt/raid bindings, pause/effects gating and visual-only state safety. `UltraEnvironmentSmokeTest` covers packed map bindings, native renderer routing, the real reflection sky, fixed pool overload, pause/battery and gated DOF. Mobile environment passes are recorded in [gpu-repairs.json](gpu-repairs.json); the actual Forward+ run passed19checks in [forward-environment.json](forward-environment.json). `build_ultra_floor.py` completed under Blender5.2.2; Python syntax and whitespace checks passed. Final native execution and measured performance/memory are documented in [README.md](README.md). The 60fps/200MB target remains unmet.

Rebuild: `Blender --background --factory-startup --python tools/build_ultra_floor.py`. This tool writes floor assets/material metadata only; actor authoring is separate. The top-level `assets/mobile25d/catalog.json.floor` is synchronized to `floor/material.json` after the independent actor build.
