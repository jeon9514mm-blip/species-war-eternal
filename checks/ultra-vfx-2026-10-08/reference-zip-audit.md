# Meta Ultra v46 ZIP inspection

The second supplied Meta attachment was downloaded by direct HTTP after two browser attempts timed out. The exact **95,538-byte** ZIP is archived at `assets/art-direction/meta-ultra-reference/ultra-v46-reference.zip`. SHA-256: `d0034aa66f4e876775a449c33158257e1bfd5828bdf7c625dd888eb6defec102`. ZIP CRC integrity passed. All **32 members** were decoded and read as UTF-8 data; none were executed or extracted as Godot scripts.

The archive contains **30 hero parameter scripts**, one shared `Ultra_Detail_98_v46.gd` and one HTML design brief. All thirty hero scripts normalize to **one identical template** when hero/skill names are removed. All **120 slot-specific skill names match exactly** the registered `hero-catalog.json`; mismatch count **0**. No image, shader asset, mesh or audio file is included. The HTML repeats the fifteen Ultra requests and shows six named heroes plus a statement covering the other twenty-four; it is not a captured animation or visual-quality benchmark.

The shared renderer helpers `spawn_caster_98`, `spawn_projectile_98` and `spawn_impact_98` are `pass` stubs. A flag such as `gpu=true`, `ssr=true` or `motion_blur=true` in a returned dictionary does not implement that feature. Camera feedback assumes six custom methods on a `Camera2D`, but the ZIP supplies no such implementation and this game uses a real `Camera3D` viewport.

The supplied slowdown sets `Engine.time_scale=0.08`, waits on a scaled 0.18-second timer, then forces time scale to1.0. At stable0.08scale, that timer nominally lasts **2.25 seconds of wall time**, and ignores prior battle speed/lifecycle restoration. The game implementation uses a monotonic **180ms wall deadline**, a three-second ultimate cooldown and restoration of the prior scale onexpiry/pause/off/exit.
