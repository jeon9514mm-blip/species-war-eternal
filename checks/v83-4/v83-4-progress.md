## 구현

### 연구 재배분

`영웅 성장 → 연구 포인트 재배분 → 초안 수정 → 변경 효과 미리보기 → 확인`.
공격/생존/기능 각각 0~10, 총투자는 실제 영웅 레벨의 기존 예산(3레벨당1, 최대30)을 초과할 수 없다. 현재 배분을 줄여 미사용 포인트로 되돌리거나 다른 분야에 옮길 수 있다. 비용0, 획득 총량/레벨/경험치/장비/조각/재화는 재분배하지 않는다.

초안과 미리보기는 별도 Dictionary이며 실제 영웅 트리에 쓰지 않는다. 초안 수정 시 기존 확인을 무효화한다. 확인 시 진영/해금/성장/장비/프리셋 설정/화면/수정 일련번호를 다시 검사한다. 이중 탭/오래된 미리보기/전투·연습 중/저장 대기는 거부한다. 무변경 확정은 저장하지 않는다.

확정하면 연구 한 건을 동기적으로 교체하고 능력치 갱신 후 저장한다. 저장 실패 시 메모리에 적용된 배분과 사용 가능 포인트를 유지하고 공통 저장 대기로 막는다. 재저장은 포인트를 다시 반환하지 않고 현재 스냅샷만 쓴다. 지속적인 저장 실패 중 강제 종료 무손실을 보증하지 않는다.

기존 통합 프리셋은 현재 연구를 복사/되돌리지 않는다. 새 후반 선택형 특성이나 연구 개편은 이번 범위가 아니다.

### 연습 레벨 맞춤

`전투 연습실 → 현재 성장 상태로 연습 / 레벨만 맞춰서 연습`.
기본값은 현재 상태다. 맞춤은 1~현재 진영에서 합류한 영웅의 최고 실제 레벨 범위이며 벤치 영웅도 상한에 포함한다. 미합류/다른 진영 영웅은 상한을 늘리지 못하고 잘못된 편성도 입장에서 거부한다.

전투 능력치와 전투력 계산의 레벨 성분에만 임시값을 공급한다. `hero_progress`를 잠시 높였다가 저장에서 되돌리는 방식이 아니다. 연구 예산/경험치/승급/돌파/장비/수호신은 실제값이다. 따라서 전체 능력치를 평준화하거나 특정 영웅이 우수함을 보장하는 모드가 아니다. 낮은 레벨로 맞출 때도 실제 연구/돌파는 그대로이며 안내에 명시했다.

일일3모드, 도달한 탑, 해당 주 심연에 연결했다. 보상/미션/횟수/최고기록 비반영 원칙을 유지하고 연습 종료·화면 이탈 시 이전 경제/전투 상태와 난수 상태를 복원한다. 전투 중 저장 금지. 실전/일반 연습/맞춤 연습 및 맞춤 레벨이 다른 분석은 비교 이력을 분리한다. 기존 최근1개/요약6개 메모리 보관이며 영구 보고서 저장은 추가하지 않았다.

## 초기 실패 및 수정

1. Godot JSON 읽기에서는 숫자가 float이며 int Dictionary와 전체 비교 시 불일치한다는 것을 작은 엔진 프로브로 재현했다. 저장 파일 값 비교만 JSON 숫자형을 같은 형태로 정규화했다. 실제 게임 로더의 정수 복원 검사는 별도로 유지했다. 검사항목을 삭제하지 않았다.
2. 초기 연습 복원에서 일반 성장 갱신 함수를 불렀더니 비어 있던 수호신 성장 항목이 초기화됐다. 경제 필드별 비교로 `pet_progress`만 변한 것을 찾았고, 일반 갱신 호출 대신 연습 시작 전 전투 런타임도 스냅샷으로 저장·직접 복원하도록 제품 코드를 수정했다. 최종 검사에서 기존/맞춤 연습 양쪽 경제 보존을 확인했다.
3. 캐시 재사용 임포트의 누락 UID 경고를 피하도록 엔진이 생성한 스크립트 UID 동반파일을 소스에 보존했다.
4. 최초 가상화면 실행은 오디오 하드웨어가 없어 ALSA 초기화 오류 후 Dummy로 전환됐다. 최종 화면 검사는 처음부터 Dummy 오디오를 명시해 다시 실행했다. 이것은 실제 음원 청취 검사가 아니다.

초기/두 번째 집중 결과와 로그를 외부 검증 폴더에 보존했다. 최초 장시간 전투 실행은 복원 문제 수정 후 교체 실행을 위해 중단했고 성공으로 세지 않았다.
