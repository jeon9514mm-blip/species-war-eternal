# v83-5 탑·심연 공략 다양화 / 진영전 1차 개선

## 상태와 기준
실제 소스 적용 후 **Godot 4.7.2.stable.official.ed1daf0bf**에서 최종 전체 스크립트 검사와 집중 시험 완료.
기준은 v83-3 전체 ZIP에 v83-4 growth-lab 패치를 적용한 v83-4다. 마지막 v83-4 결과의 소스/설정 319개 해시와 일치한 상태에서 시작했다.
v83-3 ZIP의 SHA-256: `7a2b39247db1a91ec63f1e7b51b5f332867e3aa112501fd23b03c4d1b5f3d023`.
기존 ZIP을 읽어 복원했을 뿐 신규 게임 배포 ZIP은 만들지 않았다. 디자인·계정·클라우드·온라인 서버·길드 작업은 추가하지 않았다.

## 1. 진영전 — 현재 로컬 부대전 개선
- 정찰과 실제 교전에서 전술/피로/부상/지형 계산을 공유한다. 기존 전술 계수나 교전 피해 산식을 바꾼 것이 아니다. 부상 HP 반올림 차이도 실제 권한 처리와 같은 올림으로 통일했다.
- 균형·강습·신중을 선택했을 때 정찰 전력에도 같은 보정이 반영된다. 읽기 전용 정찰로 병력/군량/수비대/난수 상태를 바꾸지 않는다.
- 전력 합계는 추정 지표다. 여러 수비대의 순차 교전, 타깃 선택, 회복에 따라 결과가 달라지므로 승리 보장 또는 확률 예측으로 표시하지 않는다.
- 출정 안내와 로컬 권한부의 입장 검사를 공유한다. 행군 중/경로/시즌/피로/부상/보급/군량 조건을 다시 검사한다. 중상을 입은 군대의 아군 영토 이동·귀환까지 막지 않는다.
- 확인창의 전술/편성/부상/경로/적 소유권/수비대가 바뀌면 재확인해야 한다. 닫힌 확인창과 중복 클릭은 새 출정 명령을 보낼 수 없다. 군량 자연 회복만으로 매번 확인창을 무효화하지 않되 현재 지불 가능 여부는 확인한다.
- 정찰 화면의 목표 찾기를 자원 확보/끊긴 보급 연결/요새 공략으로 나눴다. 실제 이동 가능한 후보만 선택하고, 목표 선택 자체로 출정·점령·군량 소비를 하지 않는다. 부상/군량/보급 등으로 적합한 후보가 없으면 없다고 안내한다.
- 전투 보고서에서 현재 부대의 전술·피로·보급·주둔을 보고 수비 등록/수도 귀환/다음 목표로 이동한다. 과거 보고서의 좌표가 아닌 현재 부대 위치 기준으로 기존 명령을 실행한다.
- 신규 진영전 타깃 정책/실시간 대규모전/온라인 PvP/자동 반격/오프라인 영토 손실은 이번 범위에 없다.

## 2. 탑·심연의 제한된 새 패턴
탑 1~9층은 그대로다. 10층부터 **마지막 무리**에 회복 지원대→차단 가능한 강타→분산 진형이 층별 순환한다.
심연의 첫 우두머리는 그대로다. **두 번째 무리부터** 주간 번호에 따라 같은 패턴 1종이 적용되며 기존 HP/공격/속도 수치 변칙과 함께 사용한다.

### 회복 지원대
지원몹은 기존 무제한 일반 지원 행동으로 내려가지 않고 전용 회복 행동만 사용한다. 4게임초 간격으로 유효한 거리의 살아 있는 우두머리를 최대HP4%씩 회복하며 **지원몹당 최대3회**다. 우두머리가 최대HP면 회복 횟수를 낭비하지 않는다. 사망·귀환·거리 조건을 확인한다.

### 차단 가능한 강타
5초 준비 주기 후 사거리 내 대상을 고정하고 2게임초 동안 경고한다. 시전 중 유효 기절을 적용하면 취소하고, 시전이 끝나도 대상이 죽거나 사거리 밖이면 불발한다. 완료 타격은 기본공격의2배를 기존 방어/보호막/회피 경로로 처리하며 다음 주기는7초다. 일시정지/앱 중단/전투 종료에서는 시계·피격을 진행하지 않는다. 회귀 중에도 경고 텍스트가 시전 상태와 분리되지 않도록 정리했다.

### 분산 진형
기존 팩을 현재 이동 가능 영역 안에서 분산한다. 길찾기/이동가능 검사와 최소 간격을 확인하고, 맵 바깥 증원이나 별도 신규 몬스터 에셋은 사용하지 않는다.

## 3. 점수·연습·보상·저장
심연 지원몹은 원래 우두머리 HP와 기본 공격 예산을 나눠 생성한다. 지원몹HP도 기존 총HP예산에 포함해 집계하며 전체 무리를 처리해야 다음 개체로 넘어간다. 회복된HP를 다시 깎은 양은 최저HP 추적 규칙에 따라 점수에 중복 반영하지 않는다.
보상 산식/횟수/레벨/연구/프리셋/저장 버전36은 유지한다. **새 행동은 전투 난이도를 변경하므로 밸런스가 전혀 안 바뀌었다고 말하지 않는다.** 현재 수치는 초기 조정값이다.
탑·심연 입장, 선택 층을 바꾸는 연습실에 패턴/대응 힌트를 표시한다. 보고서에도 패턴별 회복·시전·차단 횟수를 표시하며 비교키에 패턴ID+규칙버전을 넣는다.
기존 저장 최고점은 지우지 않는다. 과거 패턴으로 얻은 최고점과 새 패턴은 동일 조건 경쟁 기록으로 보지 않도록 화면에 명시한다. 별도 서버 랭킹·저장 이전 작업은 없다.
기존 현재레벨/맞춤레벨 무보상 연습 원칙, 실제 성장·재화·미션 보존을 유지한다.

### 자연 전투 검증
양 진영 각각 Lv60 10인 시험 편성으로 탑10·11·12층과 주간3종을 진행해 총12회 자연 완료했다. 적HP0 처리/강제승리/90초 단축을 하지 않았다. 시험 호스트에서 주간 키를 선택해 세 순환을 모두 확인했다.
심연6회는90게임초를 전부 진행했으며 실제HP 관찰값과 보고서/심연점수를 대조했다. 회복 패턴에서는 실제 회복이 발생했고 원시 피해와 실효 피해가 달라져도 중복 점수가 올라가지 않았다. 매 종료 후 경험치/장비/연구/재화/횟수/미션/프리셋 등 경제 상태를 대조했다.
이 고레벨 편성은 강타 전에 적을 처치하는 경우가 있어, 별도로 Lv60 3인·자동스킬 끔·탑35층 두 시도를 추가했다. 한 시도는 자연 시전/타격, 다른 시도는 자연 시전 후 **실제 상태효과 API로 기절 입력**을 줘 취소·일시정지·연습 복원을 확인했다. 이는 기절 영웅의 애니메이션부터 끝까지 검사한 전체 시나리오나 추가 자연 승리2회로 세지 않는다.

### 경고 및 초기 실패
최종 집중 시험 경고는 **3개**이며 기존 저장 실패 주입/쓰기 실패 시나리오의 예상 경고다. 실제 화면에는 드라이버VSync 변경 미지원 경고1개가 있다. 오류·경고0으로 과장하지 않는다.
초기 강타 단위 검사에서 소수점 오차로2초 발동이 한 프레임 밀리는 문제를 찾았고, 아주 작은 잔여시간을0으로 처리해 수정했다.
초기 실행기에는 과거 진영전3개 스크립트의 완료 표식을 잘못 지정해 실패로 기록했다. 실제 출력표식으로 바로잡고 최종60종 전체를 다시 실행했다. 최초 실패 로그는 보존한다.
기존 독립 피해 관찰 도구가 회복된HP의 재공격까지 합산했으므로, 생산 코드의 실효HP정의에 맞게 **독립 최저HP 추적 + 별도 원시HP 합계**로 보강했다. 테스트를 삭제하거나 강제성공시키지 않았다.
추가 강타 프로브의 첫 구성은 적을 처치한 뒤두번째시전을 기다려 실패했다. 발동/차단을 분리된 두 시도로 바꿨고, 저장 전처리와 연습 전후 비교를 섞지 않도록 저장된 기준 상태를 먼저 확보했다. 이 실패도 기록에 남겼다.
마지막 보조 정적 검사기는 `CHALLENGE_DRIVER._report_active()`를 Main의 미정의 함수로 오인했다. 외부 객체 호출과 로컬/self호출을 분리하고, 누락된 로컬 함수 검출은 유지하도록6개 단위검사를 추가했다. 게임코드는 바꾸지 않았다.

## 5. 보존·한계·재현
기존 이미지 **284개(게임280개와 이전 기록4개 포함)**와 음원24개는 v83-3 원본과 모든SHA-256이 같다. 영웅/장비/수호신/레이드 규칙·일반 사냥 제어·저장 파일 형식도 v83-4와 동일하다. 신규 이미지/음원/폰트 파일은 없다.
모든영웅조합/신규계정성장/전체층/장시간 사냥/Android실기기/강제종료유실/온라인서버보안 검증을 완료했다고 보지 않는다. 특정 영웅이 반드시 필요하지 않도록 설계했지만 모든조합의 공략 가능성을 입증한 것은 아니다.

```sh
python3 tools/run_v83_5_runtime_checks.py --godot /path/to/Godot_v4.7.2-stable_linux.x86_64 --workers 3 --timeout 600 --output /tmp/v83-5-final-results.json
python3 tools/static_validate.py
python3 tools/test_static_private_calls.py
```

이번 배포 변경분은 **깨끗한 v83-4에 git apply로 적용하는 증분 패치**다. v83-3 전체본만 있는 경우 먼저 기존 v83-4 growth-lab 패치를 적용해야 한다. v79 누적 패치와 중복 적용하지 않는다. 원래 저장 파일을 보관한다. 다음 예정은 v83-6 레이드·역할 기여 분석이며 아직 구현하지 않았다.
