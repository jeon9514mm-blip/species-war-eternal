# 움직임·방향·크기·전투 AI 검수

2026-10-07, Windows Godot 4.7.2, GTX 1050 Mobile 렌더러. 기본 표현은 전신 원화와 실제 3D 맵이다.

## 반영 내용

- 실제 이동의 좌우 성분과 공격 대상에 맞춰 시선을 유지한다. 세로/대각선 이동 및 레이드의 대기 초기화가 방향을 덮어쓰지 않는다. 작은 이동 보정에는 회전 지연을 두고 정지 시계에서는 방향도 동결한다.
- 걷기·대기 그림을 발 기준의 같은 높이로 균일하게 맞춘다. 혼잡도에 따른 프레임별 크기 변경과 사냥 자동 줌을 제거한다. 공격 자세의 숙임·무기 궤적은 원래 그림을 보존한다.
- 사냥의 첫 배치는 5열×2줄, 가로 1.22·깊이 2.30이다. 저장된 진형의 역할 순서는 유지한다. 개별 추격 범위는 지원 3.4·측면 딜러 4.6·기타 4.0으로 줄이고 앞뒤 이동은 중심에서 ±2.5로 제한하여 고정 크기의 가로 화면에 영웅이 모이도록 한다.
- 레이드 입장 줄 간격 104→88, 실제 캐릭터 분리 거리 85→80. 벽에 몰리는 경우 실제 발 좌표에서 빈 공간을 찾는다.
- 유효한 공격 위치에 들어온 영웅은 불필요하게 옆자리로 이동하지 않는다. 이동 발동 패시브와 위험에 노출된 후열은 계속 위치를 조정한다. 근접 목적지를 몸체 충돌 거리 바깥에 둔다.
- 몬스터는 접촉 위치에서 공격하고, 상대가 공격 거리 밖으로 나가면 추격한다. 주변 몬스터 순서가 바뀌었다는 이유만으로 반대편으로 빙돌지 않는다.
- 좁은 곳에 막힌 배우만 이동을 보류한다. 한 무리의 충돌 때문에 멀리 있는 다른 무리까지 전장 전체 이동이 취소되던 문제를 수정했다. 기존 시전 고정·암석·몸체 충돌 제한은 유지한다.

## 쿠키런 영상 참고 범위

사용자가 말한 ‘쿠키런 키우기’는 [공식 CookieRun: Crumble 소개](https://cookieruncrumble.com/en)와 [공식 스토어](https://play.google.com/store/apps/details?id=com.devsisters.cc)를 바탕으로 쿠키런: 크럼블로 해석했다.

[MGGames의 실제 플레이 영상](https://www.youtube.com/watch?v=uOfkBEwGbus)을 브라우저에서 구간별로 재생하고 화면을 확인했다. 전체 10분 3초를 연속 시청했다고 주장하지 않는다.

| 확인 구간 | 화면에서 관찰한 것 | 우리 게임 반영 |
|---|---|---|
| 약 2분 | 소수 영웅이 큰 보스 근처에 모여 공격한다 | 원화 크기 고정, 공격 대상 시선 |
| 약 6분, 스테이지 1-4 | 영웅이 작은 무리로 모여 짧게 이동하고 공격한다 | 좁은 첫 배치·개별 추격 범위·유효 위치 유지 |
| 6:17 전후, 스테이지 1-5 | 보스 가까이 공격하는 영웅과 뒤쪽 영웅이 함께 머문다 | 기존 역할별 접근/후열 회피 보존, 불필요한 자리 바꾸기 억제 |
| 9:03 전후 | 일반 사냥 화면 위에 튜토리얼이 표시된다 | 전투 분석 근거로 확대 해석하지 않음 |

영상에서는 내부 타깃 점수·신경망·시야 반경을 확인할 수 없다. 위 동작에서 착안하여 자체 전투 코드를 수정했다. 캐릭터·영상 픽셀·게임 코드는 가져오지 않았다. 우리 게임의 10인 파티·부대 진입·성장·보상 체계는 그대로다.
