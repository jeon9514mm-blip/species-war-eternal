# v83-3 작업·검증 보고서

최종 기준: v83-2 위에 저장 안전성·초반 가이드·무보상 연습전·통합 프리셋을 추가했다. 사용자가 이번 턴에 전체 ZIP을 요청했다. 계정·클라우드·온라인·길드와 새 그래픽 제작은 보류했다.

## 구현

- `SaveSafety`: 저장 실패 시 메모리에 반영된 보상을 유지하고 저장 대기 배너/재저장 버튼 제공. 다음 도전·소탕·연습·프리셋·진영 변경 및 이전 저장 로드를 제한한다. 정상 저장 후 해제하고 같은 보상을 다시 주지 않는다.
- 처음 20개 가이드의 일일 완료 요구를 던전·탑·심연·레이드 합계 완료로 완화했다. ID·수령 이력·보상량은 유지한다. 이후 장기 일일 목표는 그대로다.
- 연습실: 일일 던전 3종 1~3단계, 도달한 무한탑 층, 이번 주 심연을 현재 영웅/장비로 실제 자동전투한다. 입장 횟수 소진 후에도 연습할 수 있다. 별도 보상 영수증을 만들지 않고 경제 상태를 시작 전 상태로 복원한다. 실행 중 저장을 막는다.
- 연습 보고서는 실전과 분리된 비교 이력을 사용한다. 최근 보고서와 요약6개는 메모리 전용이다. 영구 기록/서버 순위/레벨 동기화는 추가하지 않았다.
- 프리셋: 진영별 P1~P3에 명단/순서·장비 ID·수호신·자동 스킬/궁극기를 저장한다. 미리보기는 상태를 변경하지 않으며 누락/중복/다른 영웅 소유/부위/역할/가방/옵션 대기를 확인한다. 장비 수량·재화를 복제하지 않고 같은 ID의 현재 강화값을 유지한다.

### 실제 전투와 합성 검사를 구분

새 실전 시험은 양 진영 각각 레벨60의 10영웅으로 골드 러시 반복, 3단계 보스 토벌, 탑5층을 자연 완료했다. 아우렐리아는 추가로 생존60게임초와 심연90게임초도 진행했다. 총10회 자연 완료와 양 진영 이탈2회다. 1/30게임초 단위로 기존 자동전투 함수를 실행했으며 적 HP 강제 삭제, 강제 승리, 제한시간 단축은 사용하지 않았다. 별도 테스트 호스트가 관찰한 실제 HP 감소와 보고서 수치도 대조했다. 완료 후 재화·경험치·장비·미션·완료 횟수·최고 기록 등의 각 필드가 기준값과 같은지 확인했다.

가이드 검사와 보상 실패 검사는 합성 데이터/실패 스텁을 사용하는 단위 검사다. 실제 신규 계정 육성 시간·실제 저장장치 고장·강제 종료 무손실 검사가 아니다. 프리셋 검사는 실제 아이템 ID 이동, 실제 저장 파일 쓰기/읽기/게임 로더, 외부 영웅 소유 충돌, 미보유 수호신, 중복 ID, 오래된 미리보기, 이전 프리셋 보존을 확인했다.

### 초기 실패와 수정

첫 기존 회귀는 38/41이었고, 동적 폰트 캐시의 종료 시 자원 누수1건도 발견했다. 별도 캐시 대신 SystemFont 리소스로 교체했다. 저장 상태를 제공하지 않던 정산 시험 호스트에는 명시적인 저장 결과를 추가하고 저장 버전35 고정 기대를36으로 갱신했다. 보상 조건을 삭제해 통과시키지 않았다.

새 전투 초기 실행에서는 취소 후 기존 캠프 튜토리얼 자동 갱신이 시험 초기값과 달라지는 것을 발견했다. 높은 성장 수치를 가진 시험 계정은 먼저 기존 캠프를 열어 튜토리얼 상태를 동기화한 뒤 경제 기준을 캡처하도록 수정했다. 제품의 튜토리얼을 끄거나 검사항목을 제거하지 않았다.

최종 전체 집중 실행에서는 44/45가 통과했다. 나머지 연습전 시험은 입장 직전의 파일 바이트를 캡처했는데, 실제 입장 시 정상적으로 한 번 저장하면서 타임스탬프가 바뀌어 잘못 실패했다. 입장 저장 성공 직후로 동결 비교의 기준을 옮겨 전투 중 파일 불변 조건을 유지했다. 제품 코드와 나머지 44개 통과 시험은 바뀌지 않았고, 변경된 시험은 별도 엔진 문법 검사 후 10회 자연 전투/2회 취소를 다시 실행했다. `final-results.json`은 이 두 실행을 명시적으로 합친 최종 판정이며 45개를 같은 시점에 모두 다시 실행했다고 표시하지 않는다.

최초 UI 시험 호스트는 PackedScene의 전체 화면 앵커가 없는 `new()`로 만들어 화면이 0폭이었다. 실제 게임과 동일한 전체 화면 앵커를 설정하고 유효 콘텐츠 크기·마지막 버튼 스크롤 접근을 검증했다. 최종 렌더링 캡처는 이 수정 뒤에 생성했다.

프리셋의 잘못된 저장 후보가 기존 기록을 먼저 덮어쓰지 않도록 후보 검증 후 한 번에 반영하도록 고쳤다. 오래된 확인 버튼에는 실제 화면 객체도 확인하도록 추가했다.

### 경고와 미검증

최종 Headless 로그에는 의도적인 `injected_write_failure` 실패 주입 경고1개가 있다. 이를 예상 결과로 별도 기록했으며 '경고0개'라고 표시하지 않는다. 실제 렌더링에는 같은 실패 주입 경고와 드라이버 VSync 변경 미지원 경고가 있다. 최종 엔진 오류는 없다.

집중45개가 과거 모든 시험의 실행을 뜻하지 않는다. Android 터치·FPS·발열·메모리·진동·청취, 신규 계정 성장 속도, 모든 영웅 조합과 장기 경제는 별도다. 저장장치 오류가 지속되는 동안 강제 종료하면 메모리 진척은 유실될 수 있다.

## 배포/저장

저장35→36. 이전 명단 전용 프리셋은 보존하고 새 통합 기록은 직접 저장해서 만든다. 원래 플레이어 저장 파일을 보관하고 예전 버전과 혼용하지 않는다. 별도 폰트 파일은 포함하지 않는다. UI는 기기 시스템 글꼴로 표시되어 모양이 기기마다 달라질 수 있다.

단일 전체 소스 ZIP이며 APK/엔진을 포함하지 않는다. 이전 누적 패치 적용 없이 새 폴더에 풀어 `project.godot`을 연다. 아카이브 CRC와 각 파일 SHA-256 재검사 결과는 `archive-verification.json`을 참고한다. 압축 만들기 전에 검증한 코드 해시와 현재 소스가 동일함을 확인했다.
